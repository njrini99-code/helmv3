## Findings

### F1 — Own-message right edge is NOT stable when metadata renders (QA-line-C reproducible)   [observed] [severity: high]
- Evidence: `MessageThreadPane.tsx:1046-1054` opens the per-message row as `flex items-end gap-2 [justify-end|justify-start]` (plain flex-row, not flex-col). The message-column `<div>` (`flex ... flex-col ... items-end`, `:1083`) opens at `:1083` and **closes at `:1254`**. The time/read-receipt block (`:1256-1270`) is declared *after* that closing `</div>` and *before* the row's own closing `</m.div>` at `:1271` — i.e. it is a **sibling flex item of the message column inside the row**, not a child nested inside the message column beneath the bubble.
- Spec: plan §8.1 — "metadata lives beneath the bubble, **inside its aligned message column**" and "The right edge of every own bubble in a same-style group is the same when time, Sent, Read, failed, or no metadata is rendered." §24.3 explicitly asks M03B to "make the QA-line-C alignment regression test fail before repair."
- Gap: because the row is `display:flex` (row axis) with two side-by-side items — `[message-column][metadata-div]` — and `justify-end` packs them together against the row's right edge, the **combined pair** is right-aligned, not each item independently. The last message of a group (`showTime === true`, `:971`) therefore renders with its bubble's right edge pushed left by `metadata-width + gap-2 (8px)` relative to every other bubble in the same group, whose rows contain only the single message-column item and so sit flush right. This is exactly the defect the plan names at §1.1/§8.1/§24.3/M-V18 ("C02's QA line C shifts inward because the receipt/time shares its horizontal row") — it is present in the *current* integrated source, not only in the old C02 screenshot the plan is comparing against. The `#1836` "prior repair" referenced in the code comment (`:1256`, "Time + read receipt (last of group, tabular-nums)") produced a metadata row that is visually below the bubble in the DOM's paint order but is structurally still a same-row sibling, not a same-column child — so the geometry regression it was meant to fix is not actually closed.
- Artboard confirmation: `Thread.dc.html:57-66` (incoming, with a reaction), `:69-81` (own reply), and `:95-101` (own, with read receipt) each wrap ONE message as a single `flex-direction: column` div containing the bubble followed by its timestamp/receipt as a child of that SAME column — e.g. `:95` opens `<div style="display: flex; flex-direction: column; align-items: flex-end; gap: 5px;">`, `:96` is the bubble, `:97-100` is the time+read-icon row, all closing at `:101` inside the one wrapper. This is the literal DOM shape §8.1 describes in prose ("metadata lives beneath the bubble, inside its aligned message column") — the approved source itself nests metadata as a same-column child, never as a row-level sibling. `MessageThreadPane.tsx`'s structure (message-column closes `:1254`, metadata sibling opens `:1256`) is a categorically different shape from what the design source builds, not just an inexact match.
- Test that would fail: mount a two-message same-sender group where the earlier message has no visible time (`showTime=false`) and the last message does (`showTime=true`); read both bubbles' `getBoundingClientRect().right` in a real (non-jsdom) layout engine — they will differ by the metadata row's rendered width + 8px. Both existing test files (`MessageThreadPane.scroll.test.ts`, `FairwayMessages.threadWidth.test.ts`) run under jsdom, which per that second file's own header comment (`FairwayMessages.threadWidth.test.ts:27-32`) "does not compute real grid/flex layout" — so **no existing test can catch this**, and none currently asserts it (confirmed by grepping both test files: neither references `getBoundingClientRect`, `.right`, or bubble alignment at all).
- Second symptom, same root cause: the message-column `<div>` (`:1083`) carries `min-w-0` and, as an un-declared-basis flex item, defaults to `flex-shrink: 1`. On a narrow viewport a long last-of-group message plus its metadata sibling exceeds the row's available width, so the column doesn't just lose right-edge alignment — it *shrinks below its own 78%/70% cap* to make room for the unconstrained metadata item beside it, narrowing the bubble itself on exactly the messages that show time/receipt.
- Proposal (not applied): move the `showTime` block inside the message-column `<div>` (before its closing at `:1254`), as a genuine last child of the `flex-col items-end` container, so it stacks vertically under the bubble and inherits the column's own right-alignment instead of competing for row space.
