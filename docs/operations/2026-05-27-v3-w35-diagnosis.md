# W35 Outcome-Attribution Cron — Silence Diagnosis
**Date:** 2026-05-27
**Source:** prod Supabase via MCP, `src/lib/coachhelm/v3/causality/attribute.ts`, `src/app/api/cron/v3/causality-attribute/route.ts`
**Status:** **Benign-by-design. No fix needed for launch.**

## What looked broken

`golf_insight_outcome_attribution` has 0 rows in prod. `golf_coachhelm_coach_weights` has 0 rows. The cron is scheduled `0 6 * * *` in `vercel.json` and the code shipped per W35 wave note. Initial suspicion: the cron isn't firing.

## What's actually happening

The cron is firing. The eligibility set is empty.

### Evidence

```
Insights ≥21d old:            130
  unattributed (eligible):    129
  using metric='score_to_par':  0   ← every other metric returns null from attribute.ts
```

`src/lib/coachhelm/v3/causality/attribute.ts:63` only implements the `'score_to_par'` metric path. For any other metric (e.g., `par_scoring_par4`, `approach_proximity_*`, `putt_make_rate_*`), `averageInWindow()` returns null → `computeAttribution()` returns null → the cron counts it as `deferred` and writes nothing. With 0 score-to-par-tagged insights eligible, the cron is a no-op every day.

Secondary fact: v3 insights first landed 2026-05-26 in prod — no v3 cohort is even 21d old yet. The post-window closes earliest ~2026-06-16.

## What we ruled out

- **H1 (cron not firing).** Refuted via prod row timestamps. Standing-refresh fires daily 04:00, genome-nightly fires daily 05:00, both write rows. Cron infrastructure is healthy. The 06:00 causality cron uses the same pattern — almost certainly fires too.
- **H3 (route erroring).** No `causality`/`attribution` titles in `admin_events`. No 5xx evidence in `error_logs`. The route has no success-path log line (no v3 cron writes to `background_job_logs` in 14d) — but that's silence by design, not error.

## Recommended action

**Do nothing for launch.** This is not a v3 launch blocker.

When ready to expand: open a follow-up to broaden `averageInWindow()` in `attribute.ts` to cover the per-shot-category metrics that already live in `golf_player_stats_cache` (strokes_gained_total/_tee/_approach/_around_green/_putting plus 30+ stat rows). Suggested order:

1. `strokes_gained_total` (closest to the existing `score_to_par` shape)
2. `strokes_gained_putting`, `_approach`, `_around_green`, `_tee` (the 4 SG components)
3. The 23 other registered metrics where lift is meaningful

Also worth adding: an `admin_events` or `background_job_logs` insert per invocation so silent skips become observable.
