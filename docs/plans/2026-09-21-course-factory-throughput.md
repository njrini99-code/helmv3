## Full-library closure workflow

The current inventory has 44 catalog layouts. Each is required to move through
the same five gates; a scene may advance through the first two gates while the
remaining evidence is being gathered, but it must never skip a gate.

| Gate | Automated work | Result | Authority it does **not** grant |
| --- | --- | --- | --- |
| Catalog | Validate facility/layout/scorecard bindings and retain source hashes | immutable layout input | a physical tee location or a player-round change |
| Visual | Build a facility fallback or route-specific candidate GLB | display-only 3D context | hole association, distance, lie, or measurement authority |
| Identity | Resolve numbered tee-to-green routes and explicit surface associations | candidate per-hole package | approval of feature boundaries or terrain accuracy |
| Physical | Acquire a single verified terrain source, validate feature provenance, and run the per-hole truth gate | physical-candidate world | production publication or One Tap eligibility |
| Admission | Review registration, per-feature confidence, package/asset hashes, and capability manifest | versioned usable capabilities | modification of a saved round, tee profile, scorecard, or raw shot |

Run low-cost catalog, route, and source checks across all layouts in parallel.
Run raster, Blender, and capture work serially under the 8 GiB disk reserve.
The factory reuses immutable source and per-hole output hashes, so a failed or
held layout does not cause successful siblings to rebuild.

### Ownership lanes

1. **Source lane:** discover and retain imagery/terrain metadata, preserve
   WKT, vertical-unit evidence, source dates, and hashes.
2. **Identity lane:** recover only numbered, source-backed route and green
   associations. It can emit display-only candidate corridors but cannot map
   one to scorecard ordinals without explicit evidence.
3. **World lane:** compile per-hole terrain and GLBs from approved inputs;
   validate export round trips and resource budgets.
4. **Review lane:** resolve registration, reviewed feature boundaries,
   confirmed absences, and capability admission.
5. **Runtime lane:** bind a round to its immutable tee/scorecard snapshot and
   approved geometry version. Visual assets never write round or scorecard
   state.

### Closure definition

For each of the 44 layouts, the audit must report exactly one of these final
states:

- `physical_admitted`: every numbered hole has a reviewed, source-backed
  package and the corresponding capability manifest;
- `visual_candidate`: a per-hole GLB exists, but source truth remains held;
- `facility_visual_only`: context renders without asserting an individual
  hole; or
- `blocked_with_remediation`: the report identifies the specific missing
  source, identity, or source-frame decision and the review/import action.

The closure report is generated by
`scripts/golf/course-geometry/audit-course-world-coverage.py`. Its counts,
not GLB count alone, are the definition of library completion.
