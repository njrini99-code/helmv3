# Agent D: legacy-cleanup — DONE

## Inspection of the 72 legacy insights

The 72 rows pre-date migration `supabase/migrations/20260422100000_insight_evidence_lifecycle.sql`,
which **added** the `evidence`, `signature`, `category`, `lifecycle_state`, `addressed_at`, and
`archived_at` columns (lines 11-17). The migration did **not** include any backfill statements:
existing rows are left with `lifecycle_state = NULL`, `evidence = NULL`, `category = NULL` and
no entries in `golf_insight_drill_attachments`.

The valid `lifecycle_state` values (from the CHECK constraint at lines 24-28) are:

```
'tentative' | 'detected' | 'matured' | 'addressed' | 'resolved' | 'archived'
```

The 72 rows were generated by the older `insight_type`-driven mining pipeline. The codebase still
defines those types in `src/lib/coachhelm/insight-types.ts:6-16` (`scoring_decline`,
`bubble_player`, `team_trend`, etc.) and the V2 engine references them at
`src/lib/coachhelm/v2/types.ts:494`. The user's three sample rows
(`team_trend / "Birdie Opportunities"`, `bubble_player / "Approach (200+ yards)..."`,
`scoring_decline / "Driving Dispersion..."`) match this old shape exactly: `insight_type` is set,
but `evidence`, `category`, `lifecycle_state`, and drill attachments are all NULL/empty because
the producers never wrote them.

The new pipeline (post-2026-04-22) writes ALL of `evidence` + `signature` + `category` +
`lifecycle_state` together — so any row missing any one of them is unambiguously legacy.

## Feed-read behavior

The new evidence-backed surfaces correctly filter legacy rows out:

- `src/app/golf/actions/insight-delivery.ts:101` defines
  `VISIBLE_LIFECYCLE_STATES = ['detected','matured','addressed','resolved']`,
  applied via `.in('lifecycle_state', [...VISIBLE_LIFECYCLE_STATES])` at lines
  188, 210, 259, 333, 398, 449. Each query also adds `.not('evidence', 'is', null)` (lines 187, 209).
  This covers `getTopInsightForPlayer`, `getInsightsForPlayer`, `getInsightsForCoach`,
  which feed the player Hub, `/dashboard/coachhelm`, Round Review, and the new
  coach `/dashboard/insights` page.
- `src/app/golf/actions/insights.ts:2425-2426` (`loadEvidenceBackedInsights`) filters with
  `.not('evidence', 'is', null)` and `.in('lifecycle_state', ['detected','matured','addressed'])`.
- `src/app/api/cron/coachhelm-insight-lifecycle/route.ts:82` only progresses rows already
  in `('tentative','detected','matured','addressed')` — so legacy `NULL` rows are ignored
  by the nightly cron and will never auto-archive.

The legacy/coach surfaces, however, do **not** filter on `lifecycle_state` or `evidence`:

- `src/app/golf/actions/alerts.ts:52-71` (`getCoachAlerts`) — feeds `/dashboard/alerts`.
  Filters only on `coach_id`, `dismissed=false`, `acknowledged_at IS NULL`. Legacy rows pass.
- `src/app/golf/actions/insights.ts:1037-1051` (`getActiveInsights`). Filters only on
  `coach_id`, `status='active'`. Legacy rows pass.
- `src/app/golf/actions/intelligence-dashboard.ts:228-238` (`getTeamInsightsSummary`) —
  feeds `/dashboard/intelligence`. Filters only on `team_id`, `dismissed=false`. Legacy rows pass.
- `src/app/golf/actions/insight-management.ts:88-97` (`searchInsights`) — coach search UI.
  No lifecycle/evidence filter.

So the 72 legacy rows are leaking onto the coach Alerts, Intelligence, and search surfaces
(and any place `getActiveInsights` is consumed). They do NOT leak onto player feeds (those
all go through `insight-delivery.ts` or `loadEvidenceBackedInsights`).

## Recommendation: EXPIRE

Backfilling is the wrong call: the 72 rows have no source `evidence` payload — the old miner
never persisted `your_value`, `comparison_value`, `confidence_factors`, `window_days`, or any
of the fields `EvidenceInsight` and the cron at `route.ts:222-263` rely on. Synthesizing those
fields would produce fake "evidence-backed" insights with fabricated stroke-impact and
confidence numbers, polluting the very ranking signal the new system was built to make
trustworthy. Worse, none of the 72 have drill attachments, so even after a backfill they'd
render as half-broken cards (no drill chips, no comparison numbers, no movement chart). The
right move is to mark them `archived` with `archived_at = NOW()`: the cron's Rule 3 (hard
archive at >90d) and Rule 2 (detected + 0 movement + >30d) already define this same outcome
for ageing rows; we are simply applying the cron's terminal state to rows the cron can't see
because their `lifecycle_state` is NULL. After expiry, when the next round of insights runs
through the new pipeline, fresh evidence-backed rows will replace them per-player.

## SQL script (user runs this)

```sql
-- ============================================================================
-- Agent D: Expire pre-2026-04-22 legacy insights from golf_coach_insights.
-- Idempotent: re-running is a no-op once all legacy rows are archived.
--
-- A "legacy" row is unambiguously identified by:
--   lifecycle_state IS NULL  AND  evidence IS NULL
-- because the post-2026-04-22 producers always write both together.
--
-- Expected impact (per user's snapshot): 72 rows updated.
--
-- Run on production via Supabase SQL editor or psql with a service-role
-- connection. Wrap in a transaction so we can verify counts before commit.
-- ============================================================================

BEGIN;

-- 1. Sanity check: how many rows match the legacy predicate?
--    Expect ~72 on first run, 0 on subsequent runs.
SELECT
  COUNT(*) FILTER (WHERE lifecycle_state IS NULL AND evidence IS NULL) AS legacy_rows,
  COUNT(*) FILTER (WHERE lifecycle_state IS NOT NULL)                  AS new_pipeline_rows,
  COUNT(*)                                                              AS total_rows
FROM public.golf_coach_insights;

-- 2. Optional: surface what we are about to expire so the user can eyeball it.
SELECT id, coach_id, player_id, insight_type, title, created_at
FROM public.golf_coach_insights
WHERE lifecycle_state IS NULL
  AND evidence       IS NULL
ORDER BY created_at DESC
LIMIT 20;

-- 3. Expire the legacy cohort.
--    - lifecycle_state = 'archived'  -> excluded from VISIBLE_LIFECYCLE_STATES
--    - archived_at     = NOW()       -> matches cron Rule 2/3 terminal state
--    - status          = 'dismissed' -> filters from alerts.ts (dismissed=false)
--                                       and intelligence-dashboard.ts (dismissed=false)
--    - dismissed       = true        -> same; legacy bool flag still in use
--    - dismissed_at    = NOW()       -> audit trail
--    - updated_at      = NOW()       -> standard
--
--    We deliberately do NOT touch `evidence`, `signature`, `category`, or
--    drill attachments — leaving them NULL preserves the "this was legacy"
--    forensic signal in case we ever want to re-mine them.
UPDATE public.golf_coach_insights
SET
  lifecycle_state = 'archived',
  archived_at     = COALESCE(archived_at, NOW()),
  status          = 'dismissed',
  dismissed       = TRUE,
  dismissed_at    = COALESCE(dismissed_at, NOW()),
  updated_at      = NOW()
WHERE lifecycle_state IS NULL
  AND evidence       IS NULL;

-- 4. Verify post-update state. Expect:
--      legacy_rows    = 0
--      archived_rows  = (previous legacy_rows count)
SELECT
  COUNT(*) FILTER (WHERE lifecycle_state IS NULL  AND evidence IS NULL)            AS legacy_rows_remaining,
  COUNT(*) FILTER (WHERE lifecycle_state = 'archived')                              AS archived_rows,
  COUNT(*) FILTER (WHERE lifecycle_state IN ('detected','matured','addressed'))    AS visible_rows
FROM public.golf_coach_insights;

-- If legacy_rows_remaining = 0 and the archived_rows count matches the pre-update
-- legacy_rows count, the migration is clean.
COMMIT;
-- If anything looks wrong: ROLLBACK; instead.
```
