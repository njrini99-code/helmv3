## Round Review Wiring Gaps

### Confirmed Gaps (High confidence)

- **`src/hooks/coachhelm/useRoundReviewV2.ts:277-304`** — Hardcoded `playerAverages` fallback (totalScore: 72, putts: 32, fairwayPct: 50, etc.) is shoved into the `RoundReview` object whenever `generate()` runs. These literal "league-ish averages" are then surfaced anywhere the legacy `review.playerAverages` block is rendered. **Severity: Major.** **Fix:** populate `playerAverages` from the same `getStatAverages(playerId)` server action that the review page already calls (`src/app/golf/actions/round-review-system.ts:1506`), or drop the field and rely on `RoundStatsComparison` which already uses real averages.

- **Two parallel review surfaces with diverging data paths.** The detail page `src/app/golf/(dashboard)/dashboard/rounds/[id]/page.tsx:189` renders `<RoundReviewViewer>` (client hook -> `useRoundReviewV2`), while a SEPARATE route `src/app/golf/(dashboard)/dashboard/rounds/[id]/review/page.tsx` renders `<RoundReviewDisplay> + <RoundStatsComparison> + <V2ReviewSummary>` and calls `generateAndStoreRoundReview` directly. Detail page never links to the `/review` route. The only inbound link to `/review` is from `players/[playerId]/player-insight-client.tsx:818`. **Severity: Major.** **Fix:** decide which review surface is canonical — either delete `[id]/review/` (review already lives inside `[id]`) or replace the inline `<RoundReviewViewer>` with a Link to `/review` and add a CTA from the detail header.

- **API endpoint `/api/golf/rounds/generate-review` is dead code in the user-facing flow.** `src/app/api/golf/rounds/generate-review/route.ts` is the only file under `src/app/api/golf/rounds/**`, but nothing under `src/app/golf/**`, `src/components/golf/**`, or `src/hooks/**` calls `fetch('/api/golf/rounds/generate-review'`. Both surfaces (`useRoundReviewV2` and `[id]/review/page.tsx`) go through server actions in `round-review-system.ts` instead. Verified via grep across `src/`. **Severity: Minor (orphan endpoint, not a blocker, but adds confusion and an unused auth surface).** **Fix:** remove the route or repoint one of the two client paths through it for consistency.

- **`[id]/page.tsx:99-102`** — when round status is `in_progress` the page redirects to `/golf/dashboard/rounds/continue/${id}`, but `RoundReviewViewer` will then auto-trigger generation on the detail page for completed-but-data-thin rounds because `useRoundReviewV2.ts:381-389` auto-calls `generate()` whenever `!review && !intelligentReview`, even when there are zero shots. The auto-gen path then hits `generateAndStoreRoundReview` which short-circuits with `Round must be completed before generating a review` only for non-completed status; for completed rounds with no shots it still writes a review. **Severity: Minor.** **Fix:** gate the auto-gen on `holes.length > 0 || total_score != null`.

### Likely Gaps (Medium confidence)

- **`useRoundReviewV2.ts:117-136`** — fallback hard-string sanitization for "NaN%" suggests prior generations stored bad text in `golf_round_reviews.round_stats`. The repair is in place but the upstream cause may still exist in `generateReviewContent` / `mergeCoachHelmReviewContent` (`round-review-system.ts:1368, 1380`). Not investigated deeper; flagged for follow-up. **Severity: Minor.** **Fix:** add a unit test that round-trips a zero-data round through `generateReviewContent` and asserts no `NaN` strings escape.

- **TODO.md:84 / TODO.md:410** — claims "/golf/dashboard/rounds/[id] is not linked from anywhere" but `rounds/page.tsx:420` already wraps each round in `<Link href={\`/golf/dashboard/rounds/${round.id}\`}>`, and `roster/[id]/page.tsx:310` also links there. **Severity: Minor (stale audit data, not a wiring gap).** **Fix:** rerun the route-graph audit; this entry is a false positive.

- **Round detail page (`[id]/page.tsx`) lacks a "View Full Review" / `/review` link**, while the `[id]/review` page itself contains "View Full Stats" links pointing back to `[id]`. The two pages reference each other in only one direction. **Severity: Minor.** **Fix:** add a link from the detail page header (next to "View All Stats") to `/golf/dashboard/rounds/${id}/review`, OR collapse the routes.

### Inconclusive

- `RoundReviewDisplay.tsx`, `RoundStatsComparison.tsx`, `V2ReviewSummary.tsx`, `V2PatternsSection.tsx`, `V2CausalInsights.tsx`, `V2PredictionCard.tsx` — not opened in detail. No marker strings found via grep, but they could still contain placeholder copy. **Severity: unknown.** **Fix:** spot-read each before sign-off.

- `coachhelm/v2/orchestrator.ts:420-426` — when `prioritizedInsights` is empty, the review falls back to a static neutral message ("The round has been analyzed, but there is not yet enough evidence to surface a high-confidence takeaway."). Whether this is reached frequently in practice depends on how often `buildRoundSpecificInsights` returns empty; not measured. **Severity: Minor (intentional fallback, but worth verifying on real data).**

### Summary

Round Review is **mostly wired** end-to-end with real data. Both pages (`/rounds/[id]` and `/rounds/[id]/review`) hit live Supabase tables (`golf_rounds`, `golf_holes`, `golf_shots`, `golf_round_reviews`, `golf_players`), the V2 engine (`coachHelmIntelligence.generateRoundReview`) is invoked from `round-review-system.ts:1377`, and the list page contains zero placeholders or mocks beyond legitimate input `placeholder=` attributes. The single biggest blocker is **the duplicated review surface**: the detail page embeds `RoundReviewViewer` AND a separate `/review` route renders a different review composition with different averages logic — players reach one or the other depending on the entry point, and the legacy V1 hook (`useRoundReviewV2.ts:277-304`) silently injects hardcoded league-average numbers into the V1 fallback. Pick one canonical review page, route the other to it, and replace the hardcoded `playerAverages` with the existing `getStatAverages` action.
