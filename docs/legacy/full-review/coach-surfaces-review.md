## Top wiring gaps (ranked)

1. **[BLOCKER] `coachhelm-analytics.ts:1082-1122`** — `generateMockInsightEffectiveness` / `generateMockPredictionPerformance` are the sole fallback when the 0-row analytics rollup tables (`golf_insight_effectiveness`, `golf_prediction_model_performance`) and even the raw `golf_predictions` validations come up empty. Production will always hit this branch because `was_accurate`/`validated_at` are not yet being populated by any cron, so the Predictions and Insights tabs show empty charts with zeroed summary cards but no "no data yet" copy. Fix sketch: either (a) ship the rollup cron that fills `golf_insight_effectiveness`, or (b) replace the mock-shaped returns with explicit `success:true, empty:true` and let the panel render a real empty-state card with copy like "Effectiveness tracking starts after the first 30 days of tagged outcomes."
2. **[MAJOR] `intelligence-dashboard.ts:509-535` (also 416-453)** — `generateTeamCorrelations` returns 2 hardcoded "Fairways → Greens" / "Putting → Scoring" discoveries with fixed correlation numbers (0.65, -0.7) and `isDefault:true`, presented to the coach as if mined from their team. There is no UI treatment that hides `isDefault` rows or labels them as illustrative. Fix sketch: filter `isDefault===true` out of any list rendered to coaches, or render with a "Sample relationship — needs more rounds" badge.
3. **[MAJOR] CoachHelm Analytics summary card "Strokes Saved"** — `coachhelm-analytics.ts:676-686` reads `lifecycle_state='resolved'` rows from `golf_patterns_v2`. Post the 22,113-row pattern purge there are 4 patterns total and `golf_patterns_v2.resolved_at` is essentially never set, so this number is 0 and the panel surfaces "0 strokes saved" as the headline KPI. Fix sketch: hide the card when `patternsDetected===0` or replace headline with `activePatternsCount`.
4. **[MAJOR] Team Stats AI column always renders dashes for empty teams** — `stats/team/page.tsx:317-330` passes `intelligenceByPlayer={}` when `intelligenceResult.success===false`, and the table's `ai_rating` sort column then sorts every player to the bottom (team-stats-table.tsx:131-134). For coaches whose team has no `golf_player_stats_cache` entries this is silent, not signposted. Fix sketch: render an inline tooltip / banner when intelligence fetch fails, or hide the AI column entirely.
5. **[MAJOR] `alerts.ts:20-130` `getCoachAlerts` is dead code** — the Alerts page no longer imports it (uses `getInsightsForCoach` instead, page.tsx:32-34); only `generateAlerts`, `acknowledgeAlert`, `dismissAlert`, `dismissAllAlerts`, `acknowledgeAllAlerts` are still referenced from this file (and only `generateAlerts` from the page). `getCoachAlerts`, `getAlertCounts`, `acknowledgeAllAlerts`, `dismissAllAlerts` look orphaned. Fix sketch: ripgrep imports, delete unreferenced exports.
6. **[MINOR] Intelligence Hub redirects mid-fetch** — `intelligence/page.tsx:47-49` calls `redirect('/golf/dashboard')` when `teamId===null`, which silently bounces a coach with an org but no team. Fix sketch: render an explicit "Create your team to unlock intelligence" empty state instead.

## Summary

Coach AI surfaces are mostly wired with real data flow: Alerts, Insights, Patterns, Development Plans, Coaching Settings, Team Stats, and Create Qualifier all read/write live tables with proper auth and would be useful to a coach today. The two soft spots are CoachHelm Analytics (entirely a skeleton against three 0-row rollup tables, with misleadingly named "Mock" fallback generators that emit zero-shaped data) and the "Correlations" subtab inside the Intelligence Hub's Deep Analysis (always shows 2 hardcoded relationships flagged `isDefault:true` that the UI never differentiates from real findings). Replace those two surfaces' empty paths with explicit empty-state UI and the coach surface area is shippable.
