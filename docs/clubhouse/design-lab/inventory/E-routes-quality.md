## 6. Governance gaps (what no check enforces)

Verified absences unless marked inferred.

1. **No required UI check.** Presentation gate, pixels, motion gate, popup quality, CSS ratchet, catalog check, a11y scan, journeys and prod lane are all in workflows outside the required set (`CI aggregate`, `Review Gate aggregate`, CodeQL, `block-historical-edits`). Only `clubhouse:check` and Vitest-based scanners run in CI aggregate. `QUALITY_TOOLING.md` says so explicitly.
2. **Raw values in TSX.** No ESLint rule for hex, px, inline `style` colour, magic `z-index` in Clubhouse; the CSS counters hold 513 hex, 1,148 raw shadows, 178 raw motion, 5 raw radius (ceilings, not zero) and run only in the non-required workflow.
3. **Duplicate components.** `lint:duplicate-exports` is export-name only; nothing detects two components with the same job (the catalog lists 670 components but is "a source inventory", not a similarity check). `clubhouse:check` prevents duplicate CSS class anchors across page stylesheets only. Gap: no check for a new `Foo` button/chip/sheet that bypasses `ui/Button`, `ui/Modal`, `ui/Menu` (the raw-button rule is switched **off** for Clubhouse).
4. **State coverage.** No per-screen requirement of loading/empty/error/partial/offline/long-text/permission-denied. `state-table.test.ts` covers 15 keys with 3-5 states each; routes whose `loading.tsx` skeleton has no fixture are not enumerated (e.g. PracticeHours, CoursePage, NotFound, RoundRecover).
5. **Visual regression cannot fail a PR.** Baselines come from a nightly artifact; PR compare `continue-on-error: true`; only the 18 gate keys are covered; no tournaments, practice home/library/builder/print, recruiting, calendar, qualifiers, settings, auth.
6. **Dark mode:** gate+pixels (18 keys) only; a11y dark advisory; no dark for 40+ keys; dark switch uses the attribute `data-fw-theme` set by the test (not the app's real toggle path, inferred from `clubhouse-gate.spec.ts:46`).

No keyboard-journey test per screen (only popups, polls), no screen-reader label/order assertions beyond `aria-label-roles.test.tsx`, no focus-visible capture, no Dynamic Type test except `dynamic-type.test.tsx` (jsdom), no `prefers-contrast`/forced-colors check, no tap-target check outside gate keys.
