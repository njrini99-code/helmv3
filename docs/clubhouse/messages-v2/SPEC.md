## How to read an item

```
MSG-nnn  Title                                  [Pkg X]  [phone | desk | both]
  Ref:    the artifact hash that draws it (#<state>-<phone|desk>-<light|dark>[-reduce][-xxl][-w430][-w1280][-shot])
  Layout: exact values from the HTML/CSS (px are CSS px at Text Size k = 1; "k" scales type)
  Copy:   exact strings, in quotes
  States: loading / empty / error / long / unread / muted / group vs DM ...
```

- `Pkg` is the suggested owner (A inbox, pins, search; B thread, composer, send, typing, date pill, jump; C overlays; D polls, files, photos, details, mute, empty states, desktop layout). PLAN.md has the final file ownership.
- "Phone" is the 390 pt viewport (402 x 874 frame in the artifact, 390 x 844 in shot mode), with a 430 pt variant (`-w430`, 20 px edge). "Desk" is 1280 x 800 (`-w1280`) or 1440 x 900.
- k = Text Size scale: Aa 1, Aa+ 1.12, Aa++ 1.26, XXL 1.353 (23/17). Every `calc(Npx * k)` below follows iPhone Text Size. The phone text floor is 12 px (Clubhouse audit F09): nothing under 12 px at k = 1.
- Hash route list (the artifact's `ROUTES`): inbox, unread, thread, team, typing, times, poll, votes, seen, hold, holdseen, react, attach, file, reply, jump, details, groupdetails, mute, empty, new, pollnew, edit, rowtyping, grouptyping, failed, long, longinbox, loading, datepill, toast, rowmenu, pinlimit, fresh. Each item names the closest hash.
- NOT PRODUCT (device simulation, do not build): the phone frame, island, status bar, home indicator, the proposal page header controls (Device / Theme / Reduce Motion / Text Size segs), the stage caption, Play buttons, and the drawn fake iOS keyboard (`kbHTML`, key pop, word suggestions). The keyboard BEHAVIOUR is product (MSG-307).
