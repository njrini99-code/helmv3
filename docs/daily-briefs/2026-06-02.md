## Fixed in this PR

### 1. `golf_rounds.course_par` — selecting a column that does not exist (data-integrity)
- **File:** `src/app/golf/actions/player-fingerprint.ts`
- **Root cause:** `getPlayerFingerprint` selected `course_par` from `golf_rounds`. **Verified against the live prod schema: `golf_rounds` has `score_to_par` but NO `course_par`.** PostgREST returns a 400, so `roundsResult.error` is set, `rounds` falls back to `[]`, and the **Pressure** section, **trend line**, and composite fallback silently break — plus an error is logged every time a coach opens a player's game fingerprint. (This re-lands the intent of the unmerged #197/#200; the column had crept back into the select after the redesign merges.)
- **Fix:** drop `course_par` from the select; compute the pressure/trend/vs-par metrics from the real `score_to_par` column (identical semantics: `score_to_par == total_score − par`).
- **Verified:** 12/12 `player-fingerprint.test.ts` pass (rls/unit/integration).

### 2. Sentry **4C** — "Functions cannot be passed directly to Client Components" on `/golf/dashboard/qualifiers`
- **File:** `src/components/fairway/pages/qualifiers/FairwayQualifiers.tsx`
- **Root cause:** the file was **missing its `'use client'` directive** (line 1 was a JSDoc block), so it was a Server Component that renders client primitives and uses `<Surface as={Link}>`. `Surface` is a `forwardRef` defined in a server module — its `{$$typeof, render, displayName}` shape is exactly the object in the error, caught during Flight serialization. Every one of ~90 sibling Fairway page components (and the only other `Surface as={Link}` call site) is already `'use client'`; this file was the lone outlier.
- **Fix:** add `'use client';` as line 1 (codebase-standard, one line). Preserves Next `<Link>` nav, framer-motion entrances, and all hover transitions.
- **Scope note:** only fires when `NEXT_PUBLIC_REDESIGN=true`; the 29 events were a local QA run (0 users). Real defect regardless.

### 3. Sentry **3** / React **#418** — hydration mismatch on `/golf/dashboard`
- **Files:** `FairwayCoachDashboard.tsx`, `FairwayPlayerDashboard.tsx`, `player-dashboard-parts.tsx` (fairway dashboard tree)
- **Root cause:** round-date renders used `toLocaleDateString('en-US', …)` with **no `timeZone`**. `golf_rounds.round_date` is a DATE column, so `new Date('YYYY-MM-DD')` is UTC-midnight; the server (UTC) and a west-of-UTC client format **different days** → hydration text mismatch **and** an off-by-one display bug. The legacy dashboard guarded these with `suppressHydrationWarning`; the Fairway rebuild dropped the guards.
- **Fix:** pin the three date formatters to `timeZone: 'UTC'`. Deterministic across server/client **and** corrects the displayed day (better than re-adding `suppressHydrationWarning`).

### 4. Routine cron telemetry flooding Sentry + admin error tables → `skipSentry` (re-land of #200)
- **Files:** `src/lib/server-error-logger.ts` (+ 5 call sites)
- **Root cause:** operational signals — pattern-miner threshold starvation (Sentry **13**, **1B**), `triggerPlayerInsightsAfterRound` / `generateInsightsForTeam` skipped-legacy-record counters (Sentry **2J**), philosophy-gate filter counts (Sentry **20**) — were logged via `logServerError`/`logServerEvent`, which **captures to Sentry as issues**, "drowning out real bugs" (the logger's own words). These are the top event-count issues (58/17/12 events) and dominate `error_logs`/`admin_events`.
- **Fix:** add a `skipSentry?: boolean` flag to the logger context; when set, suppress the Sentry capture **only** (the `error_logs` + `admin_events` rows are still written, so the admin `RecentActivityFeed` keeps surfacing them and the console logs stay). Applied to the 4 telemetry sites above.
- **Verified:** 27 pattern-miner tests + 3 server-error-logger tests pass.

### 5. Sentry **4K** — `[Stats] Falling back to round-level stats: statement timeout (57014)`
- **File:** `src/app/golf/actions/stats-data.ts`
- **Root cause:** the detailed-shot stats query times out (`statement_timeout`) and **gracefully falls back** to round-level stats — the user still gets data. It was logged as a full `logServerError` (error severity → Sentry exception), turning a handled degradation into an escalating Sentry issue.
- **Fix:** mark it `skipSentry` and downgrade to `warning` (still recorded in the DB for perf tracking, no longer a Sentry exception). **Follow-up tracked separately:** the underlying query perf (optimize `queryDetailedStatsWithClient` / index review) is a larger change, out of scope for a daily review.

### 6. `main` typecheck was RED — `FairwayStatsCockpit.tsx:1311`
- **File:** `src/components/fairway/pages/coachhelm/FairwayStatsCockpit.tsx`
- **Root cause:** `selectedLie[0].toUpperCase()` — under `noUncheckedIndexedAccess`, `selectedLie[0]` is `string | undefined`. **Confirmed present on clean `origin/main`: `tsc --noEmit` (= `npm run typecheck`) was failing.** Introduced by a post-#200 redesign merge; the codebase had already standardized on `charAt(0)` for this (commit `8127a017`) but missed this instance.
- **Fix:** `selectedLie.charAt(0)` (returns `string`, never `undefined`). Restores a green typecheck on `main`.
