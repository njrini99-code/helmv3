## 1. Fleet operating rules (binding)

1. **One worktree per task.** Branch `task/<id>`. An agent may ONLY create/edit/delete the exact paths in its `files_owned`. Reading anything is fine; writing anything else is an automatic task failure — STOP and escalate, never drive-by.
2. **Wave barrier.** Wave N+1 does not start until every task in Wave N is MERGED to the integration base with its exact verification command output pasted in the PR body. A red verification never gets "fixed around" — it spawns a new root-cause task.
3. **Frozen files** are edited only by the sanctioned solo tasks below (§4 ledger). If your root cause traces into a frozen file: STOP, name the exact row/line in your PR body, hand it to the owner edit (P4.32 pattern, as P1.8/P5.2/P5.3/P5.4 already do).
4. **DB migrations:** every task owns its OWN new timestamped migration file. Additive-only (`ADD COLUMN IF NOT EXISTS`, `DROP POLICY IF EXISTS + recreate`, `ON CONFLICT DO NOTHING`). Never DROP/RENAME tables, never touch `golf_*` objects, REVOKE-first before GRANT on any new function/bucket policy. Shared prod DB with GolfHelm — a bad migration is a cross-product incident.
5. **Owner-gated waves pause the fleet.** No agent starts new work while an owner wave is open (W6 especially — worktrees are being pruned under you).
6. **≤15 files per PR**, no scope creep, no weakened assertions, upsert-only on seeds (no delete-then-reinsert), EIN—err—**verify before completion**: paste command output, not claims.
