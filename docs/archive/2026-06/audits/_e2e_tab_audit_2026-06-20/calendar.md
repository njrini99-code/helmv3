## Calendar & Events [both]

End-to-end audit of `/golf/dashboard/calendar` for both coach and player paths.
Date: 2026-06-20. Auditor: e2e tab audit subagent.

### Route / entry
- Page: `src/app/golf/(dashboard)/dashboard/calendar/page.tsx`
- Live path is the **Fairway** surface: `.env.local` has `NEXT_PUBLIC_REDESIGN=true` and prod is promoted from `main` with the redesign on (memory). The page forks at `page.tsx:210` → `FairwayCalendar`. The `EditorialCalendarSurface` legacy branch (`page.tsx:242`) is the flag-off fallback and ships unchanged. Both were traced.

### How it is actually wired (end-to-end)

**Server page (`page.tsx`)**
1. `getGolfSessionProfile()` (`page.tsx:40`) resolves role server-side (`session.ts:142-167`, `role = coach ? 'coach' : player ? 'player' : null`). Unauthenticated → `redirect('/golf/login')` (`page.tsx:41`). `isCoach` is derived here and is the single source of truth handed to all client components.
2. Team resolved via `resolveCoachTeamIdWithCookie` (coach) or `golf_team_members` (player) (`page.tsx:55-67`). Team-resolution failure THROWS to the route error boundary (`page.tsx:69-74`) rather than rendering a fake-empty calendar.
3. Events fetched from `golf_events` scoped to `team_id` and `start_time` within ±3 months, `.limit(500)` (`page.tsx:95-103`). Cancelled events are intentionally INCLUDED (they render struck-through). A failed events fetch THROWS (`page.tsx:121-123`). Players fetched via `golf_team_members → golf_players` join; timezone via `golf_team_settings` (`page.tsx:104-116`).
4. All-day dates are normalized to local-midnight to avoid TZ date-shift (`page.tsx:142-149`). `upcomingCount` computed from a stable `serverNow` (`page.tsx:199-202`).

**Fairway client (`FairwayCalendar.tsx`, the LIVE path)**
- Range-driven events + ONE stable realtime channel via `useCalendarRangeEvents` (`FairwayCalendar.tsx:185-199`; hook `use-calendar-range-events.ts`). Channel is keyed on `teamId` only, filter `team_id=eq.${teamId}`, refetches on resubscribe, `onRealtimeEvent → router.refresh()` (`use-calendar-range-events.ts:279-315`). Correctly wired — no leave/join per nav.
- Coach create/edit/delete: native `FairwayEventEditor` → `handleSaveEvent` (`FairwayCalendar.tsx:294-427`) and `handleDeleteEvent` (`429-458`). Non-recurring create → `createGolfEvent` (`golf.ts:1949`); recurring create → `createRecurringEvent` (`recurring-events.ts:416`); series edit → `editRecurringEvent` (`recurring-events.ts:553`); single edit → `updateGolfEvent` (`golf.ts:2213`); series delete → `deleteRecurringEvent` (`recurring-events.ts:846`); single delete → `deleteGolfEvent` (`golf.ts:2427`).
- Coach Week/Month REUSES the legacy `GolfCalendarWrapper` → `PremiumCalendarClient` UNCHANGED (`FairwayCalendar.tsx:817-836`) for DnD reschedule, recurring scope picker, and the legacy `EventDetailModal`. Player Week/Month/Day/Agenda render native Fairway components only (no coach tooling leaks).
- Player RSVP: `respondToEvent` (`golf.ts:3067`) → `updateRSVP` (`rsvp.ts:331`) which **upserts** `golf_event_attendance` on `(event_id,player_id)` — no destructive delete. Coach summary: `getEventRSVP` (`golf.ts:3709`) → `getEventRSVPStats`.
- Coach availability overlay: avatar rail → `getPlayerAvailability` (`golf.ts:3356`) → `getUserBusyPeriods`. Has an explicit shared-team authorization check (`golf.ts:3394-3461`).
- ICS feeds reachable for BOTH roles incl. mobile via `FairwaySubscribeSheet` → `calendar-feeds` actions (`FairwayCalendar.tsx:880-1033`).

**Mutation hygiene:** every mutating action calls `supabase.auth.getUser()` first and rejects non-coaches for create/update/delete (`golf.ts:1956-1983`, `2220-2236`, `2434-2450`). All call `revalidatePath('/golf/dashboard/calendar')` + `updateTag(CACHE_TAGS.CALENDAR)`. `deleteGolfEvent` is a SOFT cancel by default (keeps RSVP rows); hard delete is gated to cancelled/zero-attendee events. `updateGolfEvent` attendee sync is ADDITIVE-ONLY (no wipe-and-reseed). `deleteRecurringEvent` promotes the series root before deleting to avoid FK cascade wiping kept occurrences. This tab has clearly been hardened by the 2026-06-10 calendar audit and the data layer is sound.

### Expected (feature-doc #4) vs actual
- Lifecycle, create/edit (coach), RSVP/attendance (player), recurrence (this/thisAndFuture/all), soft-cancel: all present and correctly wired. ✅
- **Restore-from-cancelled: UI exists but is DEAD.** `FairwayEventEditor` and legacy `EventDetailModal` both render a "Restore event" button gated on an `onRestore` prop, but NEITHER `FairwayCalendar` nor `PremiumCalendarClient` passes `onRestore`. Cancelled events can never be un-cancelled from the UI. (matches the memory footnote "restore-from-cancelled unwired".)
- **Availability Polling (spec "✅"): not implemented.** No `availability-polling.ts` action, no poll UI, and `golf_availability_polls` / `golf_poll_responses` are never written by any code in `src/`. The coach "availability" feature is a read-only schedule overlay, not the spec's "create polls, players vote, convert to event."
- **Spec "Key Files" are largely stale:** `event-lifecycle.ts`, `availability-polling.ts`, `availability-locking.ts`, `caldav-sync.ts`, and `MonthView.tsx`/`WeekView.tsx`/`DayView.tsx` do not exist as listed. Real engine = `PremiumCalendarClient.tsx` + `golf.ts` + `recurring-events.ts` + `attendance.ts`. `golf_event_exclusions` is never written.
- **Status lifecycle inconsistency:** spec says `draft → confirmed → completed | cancelled`. `createGolfEvent` sets no status (DB default `'scheduled'`), while `createRecurringEvent` sets `'confirmed'`. So one-off and recurring events have different status strings, and nothing ever advances an event to `'completed'`. `StatusBadge` expects `draft|confirmed|cancelled|completed|pending` — a `'scheduled'` one-off won't match any branch.
