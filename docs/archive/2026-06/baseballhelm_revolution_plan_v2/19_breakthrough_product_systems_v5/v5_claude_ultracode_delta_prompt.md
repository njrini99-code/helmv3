# V5 Claude Ultracode Delta Prompt

Append this to the Claude Ultracode master prompt when you want the build agent to stop treating the work as a plan and start treating it as a product invention pass.

```text
V5 PRODUCT INVENTION OVERRIDE

Do not merely implement routes and cards. Build BaseballHelm around breakthrough product systems:

1. Signal Layer
2. Source Trust System
3. Action Conversion Engine
4. Program-Type Adaptive OS
5. Decision Ledger/Staff Action Engine
6. Player Passport
7. Performance-to-Field Engine
8. Postgame-to-Practice Engine
9. Import Dossier
10. Player Daily Contract

For every feature you implement, answer in code or UI:

- What source created this?
- Why does this matter?
- Who owns the next action?
- What can staff do now?
- What should the player see?
- What stays hidden?
- How does this become part of the player/team history?

Do not ship generic dashboards. Do not ship AI cards without source refs. Do not ship lifting as a small compliance widget. Do not ship high school, college, showcase, and JUCO as shallow text swaps.

The product should feel like a premium baseball operations platform:

- source badges are everywhere important
- signals are actionable
- imports are dossiers
- practice converts data into work
- performance converts lifting/readiness into field decisions
- player Today is simple and mobile-first
- staff Meeting Mode replaces the Google Doc
- Player Passport is source-backed proof

If a feature does not enter the source -> signal -> action -> timeline loop, cut it or defer it.
```
