# Coach Objection Handling


## Demo thesis

The demo must make a coach feel: “This understands our daily life.” Do not start with settings. Start with a realistic Tuesday inside a college baseball program.

## Demo flow

1. Coach Command Center: what changed, who needs attention, today's plan.
2. Player Timeline: one player story across games, practice, lifts, wellness, notes.
3. Import Center: upload messy stats/metrics and turn into insight.
4. Practice Planner: adjust plan based on recent weakness and availability.
5. Player Today: show the player-safe mobile view.
6. Staff Decision Room: weekly operating packet.

## Core objections

- “We already have Teamworks.” Answer: BaseballHelm is the baseball program layer, not department compliance/ops replacement.
- “We use GameChanger/StatCrew.” Answer: BaseballHelm imports official stats and connects them to practice and player meetings.
- “We use TeamBuildr.” Answer: BaseballHelm does not replace strength programming; it shows baseball implications and compliance.
- “We have spreadsheets.” Answer: BaseballHelm keeps flexibility but adds identity, permissions, rollback, AI, and timelines.
- “We use Driveline/TrackMan/Rapsodo.” Answer: BaseballHelm is where those outputs become staff decisions.
