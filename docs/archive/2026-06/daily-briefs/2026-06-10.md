## 1. Fixes in this PR (real, evidence-backed)

### 1a. Push-notifier `cookies` crash in background context — **FIXED**

`error_logs` (server): `insight-notifier: push send reported failure: `cookies` was called outside a request scope` — `warning`, 3×, last **06-09 23:38**.

Root cause: `notifyInsightLanded` (the post-write CoachHelm insight hook, fired from `upsertInsight` during cron/mining — **no HTTP request scope**) → `sendPushNotification` → `await createClient()` (`@/lib/supabase/server`), which calls `cookies()`. Outside a request, `cookies()` throws; the outer catch returned `{ success:false, error:'cookies …' }`, logged as the recurring warning. The first await — `getUserNotificationPreferences` — hit the *same* cookie client but **swallowed** the throw and silently returned DEFAULT prefs (so a player who turned push **off** still got background pushes).

Fix: both `src/lib/notifications/push.ts` (`sendPushNotification`) and `src/lib/notifications/email.ts` (`getUserNotificationPreferences`) now use `createAdminClient()` (service-role, never reads cookies, works in request **and** background contexts). Device-token reads/writes and the preference read are server-trusted and keyed by `user_id`.

### 1b. Client error-log flood from one flaky tab — **FIXED**

`error_logs` (prod): `network error` — `severity:error`, **320×**, **1 user** (`604cadcc…`), all from `https://helmsportslabs.com/golf/dashboard/rounds/new`, started 06-09 19:00, still firing 03:08 today.

Every row's context: `errorKind:"transient-network"`, `isTransientError:true`, `boundary:"route"`, `component:"GolfRoot"`, `document.visibilityState:"hidden"`, `onLine:true`. This is the `error.tsx` route boundary catching a `TypeError: network error` on a **backgrounded tab on a weak connection** — the boundary already auto-retries it and tells the user "temporarily busy… resolves quickly," yet logged it at `'high'` (→ `error`). Blast radius = **1 user**; this is log noise, not an outage.

Fix (two layers):
- `src/components/errors/RouteErrorBoundary.tsx` — auto-retried `transient-network` / `generic-load-failure` boundary errors now log at `'medium'` (→ `warning`), not `'high'`. They stay in `error_logs`/`admin_events`/Sentry for forensics but leave the `error` feed. Chunk-load / unknown errors keep `'high'`.
- `src/lib/error-logging.ts` — a module-level `shouldThrottleClientReport` de-dupes identical `(severity|component|message)` reports: first always sent, then ≤1 per 60 s, capped at 8 per tab. **Distinct** errors each get their own budget, so a genuine multi-error outage (which also spans many tabs/users) still surfaces.

### 1c. `device_tokens` RLS denial on shared devices — **FIXED**

`error_logs` (server): `Failed to register device token: new row violates row-level security policy … for table "device_tokens"` — `error`, 2×, last 06-08 23:14.

`registerDeviceToken` is auth-first (returns `UNAUTHORIZED_RETRYABLE` with no session, so `auth.uid()` is present). The denial is the **shared-device** case: `onConflict:'token'` tries to UPDATE an existing token row owned by a **different** `user_id`; the table's RLS `UPDATE USING (auth.uid() = user_id)` evaluates against the *old* owner and denies. Reassigning the device to whoever is currently signed in is the intended behavior.

Fix: `src/app/golf/actions/push-notifications.ts` runs **only that upsert** via `createAdminClient()`. Safe because the session is verified above and `user_id` is forced to `user.id` (a user can never claim a token for someone else). `unregister` / `list` stay on the RLS-scoped client.
