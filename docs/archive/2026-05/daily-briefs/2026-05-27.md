## Findings — currently firing in production

### 1. `synthesizeForPlayer` crashes for every player with a legacy null-signature row ✅ FIXED

- **Symptom:** `synthesizeForPlayer: load failed for <playerId>: Cannot read properties of null (reading 'startsWith')`
- **Where:** `src/lib/coachhelm/v3/composite/loader.ts:33`
- **Root cause:** `loadRecentInsightsForPlayer` filters out composite rows by
  calling `row.signature.startsWith('v3:composite:')`. The column is nullable
  and **20 legacy rows in `golf_coach_insights` have `signature IS NULL`**
  (verified directly against the DB). The first such row in the 30-day window
  throws and the whole synthesis pass for that player aborts.
- **Blast radius:** Fires once per player per cron sweep. Seen ~17+ unique
  players in the last 2h alone; cumulative 602 Sentry events in 12h.
- **Fix:** `row.signature?.startsWith(...)` — null-coalesce so legacy rows
  pass the filter (they can't be composites anyway).
- **Follow-up not in this PR:** backfill `signature` on legacy rows or
  add a `NOT NULL` migration once we've decided what signature to stamp
  on pre-W21 rows. Flagged for separate session.

### 2. "skipped N legacy records (insufficient sample_n)" logged as `error` ✅ FIXED

- **Symptom:** Sentry issue `JAVASCRIPT-NEXTJS-1Z` (97 events / 5d). Three
  spinoff variants in `error_logs`.
- **Where:** `src/app/golf/actions/insights.ts:1007, 3418`
- **Root cause:** Intentional pre-write filter for legacy records that don't
  meet the W17 sample-N floor. The comment in-line even calls out that this
  is an expected "log + skip" path — but `logServerError` defaults to
  `severity='error'`, so Sentry treats it as a real bug.
- **Fix:** Pass `'warning'` as the third arg in both call sites.

## Findings — latent / defensive hardening

### 3. v2 generators pass `GATED_OUT` sentinel to `attachDrills` ✅ HARDENED

- **Symptom (when it last fired, ~2 days ago):** `attachDrills.upsert failed:
  invalid input syntax for type uuid: "__gated_out__"`. Sentry issues
  `JAVASCRIPT-NEXTJS-21/22`.
- **Where:** v3 generators already check for `GATED_OUT` via
  `BaseGenerator.run()` (`generator-base.ts:138`). v2 mining code did not:
  - `src/lib/coachhelm/v2/mining/tee-strategy.ts:350`
  - `src/lib/coachhelm/v2/mining/course-management.ts:397, 572`
  - `src/lib/coachhelm/v2/mining/approach-analytics.ts:492, 570, 658`
- **Root cause:** When the active philosophy gate (W7B) suppresses the
  insight write, `upsertInsight` returns the literal string
  `'__gated_out__'` instead of a uuid. The v2 generators then unconditionally
  call `attachDrills(supabase, insightId, ...)`, which sends that sentinel
  to a uuid-typed column.
- **Fix:** Import `GATED_OUT` from the upsert module in each generator and
  short-circuit `attachDrills` when the upsert was gated. Mirrors the v3
  pattern. Test mocks at `src/test/coachhelm/v2/mining/{tee-strategy,
  approach-analytics, course-management}.test.ts` extended to expose
  `GATED_OUT` from the mocked module.
