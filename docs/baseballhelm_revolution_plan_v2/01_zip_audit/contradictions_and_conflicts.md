# Contradictions and Conflicts

## Product contradiction

V1 says BaseballHelm should be simple and daily-use, but its proposed nav creates a heavy enterprise-like product.

## Repo contradiction

V1 imagines future architecture but the repo already has baseball routes, auth, sidebar, dashboard shell, and data expectations. Building from scratch would conflict with current patterns.

## AI contradiction

V1 says AI should be grounded, but some module ideas are too magical unless the data model is fixed first.

## Import contradiction

V1 says no direct integrations, but some feature ambitions assume deeply normalized vendor data. V2 resolves this with import/attachment decisions.

## Recruiting contradiction

The product is moving toward team operating system, while older repo and docs retain recruiting-mode gravity. V2 isolates recruiting until core product works.
