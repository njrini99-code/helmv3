# V4 Program Type Variants: High School, College, Showcase, JUCO

BaseballHelm cannot be one generic baseball app with a different logo for each market. High school, college, showcase, and JUCO have different buyers, workflows, privacy concerns, daily habits, and sales demos. The underlying platform should share core objects, but the experience must be mode-aware.

## Shared Platform Foundation

All program types share:

- program
- team
- season
- player identity
- roster
- events
- calendar
- tasks
- acknowledgements
- stats
- player profile
- documents/video links
- imports
- source refs
- signals
- settings
- permissions
- AI outputs

Shared design system:

- same professional baseball OS visual language
- same source trust badges
- same role-safe visibility model
- same import dossier pattern
- same timeline pattern
- same command center skeleton

The differences are in:

- default navigation
- surface priority
- terminology
- permission bundles
- public profile rules
- guardian involvement
- recruiting/exposure prominence
- academics depth
- strength/performance depth
- demo data
- onboarding

## College Program Mode

### Buyer/User Reality

College programs care about:

- staff coordination
- player development
- game and practice prep
- academics and class conflicts
- travel
- strength and availability
- roster management
- player accountability
- staff meeting prep
- imported data from multiple systems

They may already have:

- Teamworks
- strength platform
- official stats system
- TrackMan/Rapsodo/Yakker/BaseballCloud
- spreadsheets
- Google Docs practice plans
- shared drives

BaseballHelm must not fight the entire athletic department stack. It should become the baseball staff layer.

### College Default Coach Experience

Default landing:

- Command Center

Primary nav:

- Command
- Signals
- Roster
- Practice
- Performance
- Stats
- Calendar
- Meetings
- Imports
- Team Ops

Secondary nav:

- Documents
- Messages
- Travel
- Academics
- Settings
- Recruiting/Roster Construction later

### College Player Experience

Default landing:

- Player Today

Primary nav:

- Today
- Schedule
- Tasks
- Practice
- Performance
- Development
- Stats
- Profile

Player actions:

- acknowledge events/travel
- complete check-in
- view lift assignment
- view practice group
- see player-visible coach notes
- review player-visible development goals
- upload requested files/videos if enabled

### College Must-Have Modules

- Command Center
- Signal Inbox
- Player Today
- Roster/Profile/Timeline
- Practice Intelligence
- Performance OS
- Stats/Postgame Review
- Academics/Conflicts
- Travel/Team Ops
- Staff Decision Room
- Import Dossier
- Source-cited AI
- Settings/Permissions

### College Demo Story

Best demo:

- Tuesday of conference week
- weekend series loss
- bullpen overuse
- catcher class conflict
- travel itinerary change
- strength coach notes lift non-compliance
- GameChanger/Presto stat import warning
- Rapsodo bullpen import
- AI daily brief ties all sources together
- practice plan changes because of actual sources

## High School Program Mode

### Buyer/User Reality

High school programs often have:

- smaller staffs
- one coach doing many roles
- less formal strength staff
- player/guardian communication needs
- simpler academics
- heavy player exposure/recruiting interest
- stat/game tracking
- practice organization
- showcase/camp prep

High school mode should be powerful but not overburdened with college operations.

### High School Default Coach Experience

Default landing:

- Team Command

Primary nav:

- Today
- Roster
- Schedule
- Practice
- Stats
- Player Profiles
- Development
- Communications
- Showcase
- Imports

Secondary nav:

- Performance
- Documents
- College Interest
- Settings

### High School Player Experience

Default landing:

- Player Today

Primary nav:

- Today
- Schedule
- Assignments
- Stats
- Profile
- Showcase

Player actions:

- acknowledge schedule changes
- see practice/game info
- upload profile/video/measurables if enabled
- view development assignments
- complete simple check-ins if enabled

### Guardian Mode

High school may need guardian communication.

Guardian visibility should be optional:

- schedule
- announcements
- travel details
- payment links later if needed
- player profile visibility if enabled
- no private coach notes
- no staff AI
- no other players' private data

Guardian mode should be a feature flag, not required for every high school program.

### High School Strength

High school strength should be simpler:

- workout assignment
- completion
- attendance
- simple readiness/check-in
- coach notes
- optional external strength coach

Avoid:

- complex periodization
- detailed privacy tiers unless needed

### High School Recruiting/Exposure

More prominent than college mode:

- profile completeness
- video links
- measurables
- academic/grad year info
- college interest tracking
- showcase/camp attendance

But do not build a full recruiting marketplace.

### High School Demo Story

Best demo:

- varsity team preparing for district game
- several players need updated profile/video
- one player has showcase invite
- practice plan uses recent game stats
- coach sends announcement requiring acknowledgement
- basic lift/check-in completed by players
- player profile packet is clean and source-labeled

## Showcase Organization Mode

### Buyer/User Reality

Showcase organizations care about:

- event rosters
- measurable collection
- verified player profiles
- video/doc links
- schedule/report times
- scout/college coach packets
- player exposure
- event operations
- imports from testing devices or spreadsheets

They may not need:

- deep daily practice planner
- academics/class schedule
- season-long lift compliance
- college-style travel ops

### Showcase Default Staff Experience

Default landing:

- Event Command

Primary nav:

- Events
- Rosters
- Player Profiles
- Measurables
- Video/Documents
- Scout Packets
- Imports
- Communications
- Reports

Secondary nav:

- Teams
- Camps
- Interest
- Settings

### Showcase Player Experience

Default landing:

- Event Today

Primary nav:

- Schedule
- Profile
- Measurables
- Video
- Tasks
- Interest

Player actions:

- confirm attendance
- complete profile
- upload video
- view report time
- see visibility status

### Showcase Measurables

Fields:

- 60-yard dash
- 10-yard split
- exit velocity
- throwing velocity
- catcher pop time
- pitcher velocity
- spin rate
- height/weight
- bats/throws
- positions
- verified/unverified flag
- source/event

Source trust:

- verified at event
- coach-entered
- imported from device
- player-entered
- unreviewed

### Scout Packet

Scout packet should include:

- event roster
- player profile summaries
- verified measurables
- video links
- contact rules
- source badges
- exportable PDF later

### Showcase Demo Story

Best demo:

- weekend showcase
- imported roster from spreadsheet
- measurables collected
- video links attached
- two low-confidence player matches resolved
- scout packet generated
- player profile visibility checked

## Program Type Settings

Settings should include:

- program type

- terminology pack
- player profile visibility
- guardian access
- showcase/scout access
- academic module enabled
- travel module enabled
- performance module depth
- recruiting/exposure module enabled

- player self-editing allowed
- video uploads allowed
- import templates enabled

## Program Type Acceptance

V4 is not complete unless:

- college mode feels like team operations
- high school mode feels like team plus exposure
- showcase mode feels like event/player profile operations
- JUCO mode bridges college operations and exposure
- player experience changes by context
- settings control features instead of hard-coded copies
- shared objects prevent duplicate codebases
