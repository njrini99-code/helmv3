# INC-2026-07-29-08 — Round reviews billed a free-tier AI account by accident and served templates for over two weeks, and topping up the wrong console changed nothing

- **id:** INC-2026-07-29-08
- **feature_id:** coachhelm (registry key: `coachhelm_ai`; code: `src/lib/coachhelm/v3/llm/compose.ts`, `src/lib/ai/model-provider.ts`)
- **first_seen:** ~2026-07-29 (date approximate; time-of-day unknown — the only source is the fix's own account, "every round review served its template since 07-29"; not independently corroborated against `golf_coachhelm_llm_calls` for this backfill)
- **resolved:** 2026-08-13T23:24:28-04:00 / 2026-08-14T03:24:28Z (commit `dbbe593dc`, PR #1446 opened 2026-08-14T01:30:52Z, closed 2026-08-14T03:24:28Z)
- **severity:** HIGH (a flagship AI feature was silently 100% template-fallback for roughly two weeks, and the platform *looked* healthy throughout because a sibling call site was unaffected)
- **classification:** DEPENDENCY_OUTAGE (primary — wrong billing account, not a code-logic defect in the composer itself) / AI_QUALITY_REGRESSION (secondary — every affected round review silently degraded to the deterministic template) / TELEMETRY_DEFECT (tertiary — the failure was invisible precisely because coach chat, on the correct account, stayed healthy)
- **status:** resolved (this call site); note scope below — this incident covers only the CoachHelm/round-review portion of a wider three-site fix

## Summary

The Vercel AI Gateway and the Anthropic API are **different billing
accounts.** A bare `'anthropic/…'` model string routes through the Gateway
on the project's OIDC token (there was no `AI_GATEWAY_API_KEY`) and bills
the Vercel team balance; wrapping the model id in `anthropic(…)` uses
`ANTHROPIC_API_KEY` and bills the Anthropic console directly. Three call
sites across the platform each chose independently which path to use, and
only one chose correctly. `v3/llm/compose.ts` — the CoachHelm round-review
composer — used the bare string and therefore billed the Gateway's
**free-tier** balance, which answered every request with *"Free tier
users do not have access to this model. Upgrade to paid credits."* Every
round review since roughly 2026-07-29 silently fell back to the
deterministic template. `chat/stream/route.ts` already had the correct
branch, so coach chat kept working the whole time — which is exactly why
the platform looked fine and nobody noticed the round-review path was
dead. Topping up the **Anthropic** console — the obvious response to an
"upgrade to paid credits" message — changed nothing, because the failing
call was never billing that account.

## Root cause (verified)

Model-provider selection (bare Gateway string vs. wrapped
`anthropic()` call) was decided independently at each of three call sites
instead of in one shared place, so there was nothing structurally
preventing two of the three from choosing wrong — and two did:
`v3/llm/compose.ts` (this incident) and `golf/schedule-vision.ts` ×2 (a
calendar_events-feature defect, out of scope for this incident — every
class-schedule import failed for the same underlying reason, tracked by
the calendar/team-operations incident owner if not already captured).

## User impact

Every round review generated in the affected window was the deterministic
template, not the conversational, evidence-grounded review CoachHelm is
meant to produce — the platform's stated flagship differentiator. This
compounds directly with the citation-verifier discard bugs in this same
feature area (`INC-2026-08-16-09`, `INC-2026-08-17-02`): during any period
where both defects overlapped, a round review could fail to reach a real
LLM call *at all* (this incident) or reach one and still be discarded post-
hoc by an over-strict verifier (the citation-chain incidents) — two
independent ways to end up at the same template fallback, which is worth
knowing if anyone tries to retroactively estimate how many real reviews
were lost during the affected window using only one of the two failure
modes.

## Repair

`dbbe593dc` (#1446, merged 2026-08-14T03:24:28Z), CoachHelm-relevant portion:

- Model-provider choice now lives in one place, `src/lib/ai/model-provider.ts`.
  `chat/stream` was changed to derive its model from `MODEL_FOR_TASK`
  instead of naming the model a second time independently, so the one
  call site that was already correct no longer has its own, separate
  opportunity to drift.
- `model_id` stays Gateway-prefixed everywhere it is priced or logged —
  the cost table keys on it, and an unrecognized key bills at **15x** the
  real rate, so the fix was explicit about not changing the *logged*
  identifier even while changing which account actually gets billed.
- A related Bridge-side companion fix in the same PR: an action that
  itself classifies a provider fault code (`schedule-image.ts`, logging
  `provider_vercel_ai_gateway_credit_exhausted`) was found to sometimes
  lose that classification on a second occurrence, recording
  `errorCode: null` the second time — `auto-resolve.ts` exempts a
  fingerprint from release-based auto-closure only via
  `isOperatorGatedFaultCode(metadata.errorCode)`, so the unclassified copy
  was eligible to be auto-resolved by the next deploy while the underlying
  account was still out of credit. Fixed by carrying the provider fault
  code through the returned envelope rather than re-deriving it per
  occurrence.

## Recurrence risk

Model-provider selection is now centralized, which removes the *specific*
mechanism that caused this (independent per-call-site choice), but any
**new** call site added without going through `model-provider.ts` could
reintroduce the same class of bug. Worth an invariant or lint rule rather
than relying on convention alone — see below.

## Invariant candidate

Yes — an ast-grep/static-analysis rule (not a runtime SQL check, since
this is a code-shape defect) flagging any AI SDK call that constructs a
model string without going through `src/lib/ai/model-provider.ts`'s
resolver. This is exactly the kind of check the Review Gate's custom
`ast-grep`/`semgrep` packs (`.coderabbit/ast-grep/`,
`.coderabbit/semgrep/helmv3.yml`) are built for, per
`.claude/rules/code-review-tooling.md` — a strong candidate for a new rule
in those packs rather than a new invariant script.

## Replay candidate

No — this was a configuration/account-routing defect, not a data-shape or
computation defect, so a fixture-based replay doesn't apply cleanly. The
static-analysis invariant above is the correct control-plane mechanism.

## Eval candidate

Not directly — the composer itself was not reached during the failure
window, so there is no generation-quality behavior to write an eval case
against for this specific incident. Indirectly relevant: any eval
harness measuring round-review quality should also assert the call
actually reached a real model (not a template fallback) as a
precondition, or a billing-account regression like this one would silently
zero out the eval's real sample size without failing any individual eval
case. (Eval-candidate assessment recorded 2026-08-21, this backfill's
authoring date; no eval case implemented as of this date.)
