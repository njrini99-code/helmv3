## Summary

`compose()`'s citation verifier requires every numeric token in a generated
round review to appear verbatim in a registered evidence set (except the
universally-safe 0/1/2/3/100), and discards the entire review — falling
back to the deterministic template — if any token fails to match. Found
via Sentry, then measured directly: **19 of 107 round_review compose()
calls (17.8%) were discarded** for failed citation verification, and every
discard in the entire `golf_coachhelm_llm_calls` table belonged to
round_review — no other task had ever failed verification. The unmatched
tokens were not hallucinations: they were the model correctly citing
figures **from its own prompt's facts block** — derived percentages like
GIR% and fairway% — that the evidence-registration step had simply never
been taught to expect. A detail worth flagging on its own: the Sentry
message format `unmatched=${unmatched_tokens.join(',')}` reads as "N
unmatched citations" but is actually **one token** — a single unverifiable
figure discards the whole narrative, not N of them.

## Chain of three same-day fixes, each correcting the last

1. **#1455 (`42712f9c4`, 2026-08-16T06:09:20Z)** — registered both renderings the model uses for
   a derived percentage (`"55.6%"` and `"56%"` are the same true fact),
   guarding null/zero denominators so a missing `gir_total` can't register
   `NaN`/`Infinity` as citable. Proven against `BASE_INPUT`'s own figures,
   two of which matched exact tokens observed failing in production.
   **The verifier itself was not loosened** — this changes what counts as
   grounded, not whether grounding is checked.
2. **#1457 (`9d39eea7d`, 2026-08-16T08:44:54Z)**, filed as an explicit correction to #1455:
   validated against the 19 real production discards and found **#1455
   recovers only 10 of 19**, not the full class as originally claimed. The
   uncovered 9 were integer tokens (`26, 18, 31, 34, 35, 41, 45, 47, 68,
   75`) that, joined against each caller's most recent round, line up with
   that round's own putts/score — real, legitimate figures, still
   unregistered. Rather than guess at a second fix (the obvious move —
   adding `9`/`18` to the verifier's SAFE set as structural golf constants
   — was explicitly **not** done, called "probably right" but "not
   proven"), the PR instead added `evidence_offered` to the failure-path
   log: the field/value pairs the verifier *did* accept, landing in
   `golf_coachhelm_llm_calls.citations`. This makes the *next* discard
   diagnosable on evidence rather than on a plausible story.
3. **#1458 (`4ef3c99be`, 2026-08-16T10:04:01Z)** — shares token extraction between registration
   and verification via a single exported `extractNumericTokens`, so the
   two paths cannot structurally drift apart again, and registers figures
   drawn from **composite-insight titles** injected into the prompt (a
   third source of legitimate numeric citations beyond the base facts
   block and derived percentages). Persona labels and goal-progress
   figures are deliberately left **unregistered** — the prompt explicitly
   instructs the model not to quote a goal's target number or date, so a
   goal figure appearing in output *should* still trip the verifier, and
   does. Greptile's review of this PR flagged one known remaining edge
   case (a signed-positive title value like `+0.24` not registering while
   the model's natural unsigned restatement `0.24` does get checked) as
   not yet fixed at merge time.

## User impact

Real coaches and players received deterministic template round reviews
instead of grounded AI-generated ones for a measured 17.8% of calls at
first diagnosis, later understood to be roughly half-covered by the first
recovery pass — meaning some fraction of round reviews were still being
silently discarded even after #1455 and #1457 shipped, until #1458's title-
figure registration closed more of the gap the same day.

## Recurrence risk — this chain is pre-history for two later, still-tracked instances

**This is the load-bearing cross-reference for this feature area.** The
same underlying defect class — a `compose()` caller instructing the model
to cite a figure while its evidence-registration step doesn't cover that
figure's source — recurred twice more after this chain, in different
`compose()` callers:

1. **2026-08-17T04:20:20Z** (commit `7feaeb545`, the day after this chain
   closed), a *different* `compose()` caller (`generateLLMRecap` /
   round-recap composer, not the round-review composer this chain patched)
   shipped with an **empty** evidence array entirely — not a coverage gap
   but a total absence. Fully documented in `INC-2026-08-17-02`, which
   also flags a **third**, still-open sibling in `coach_chat` (#1540,
   ~46% ungrounded discard rate as measured 2026-08-20/21, invisible to
   standard error-log detection).
2. **2026-08-18T13:49:37Z** (commit `c723eaa35`, "a fabricated fraction
   passed citation verification," two days after this chain closed)
   suggests the class also has a **false-negative** direction — something
   getting *through* verification that shouldn't have — which is the
   opposite failure mode from every instance in this chain and in
   `INC-2026-08-17-02`. This commit falls in the 08-17+ sibling's window
   by date; flagged here only as a forward pointer since it is clearly the
   same code family (`compose()` citation verification).

The generalized invariant proposed in `INC-2026-08-17-02` (`INV-COACHHELM-
002`, checking any `compose()` caller's sustained ungrounded-discard rate)
would have caught this chain's original 17.8% figure through the same
mechanism it was designed to catch the round-recap and `coach_chat`
instances — this chain is the earliest evidence that the invariant is
worth having, not a standalone problem that invariant doesn't already
cover.

Yes — see `INV-COACHHELM-002` in `INC-2026-08-17-02`; this chain is

## Replay candidate

Yes, and cheap given how much of it the fix commits already built: a
fixture combining (a) a `BASE_INPUT`-style facts block with derived
percentages in both renderings, (b) integer round-context values (putts,
score) unregistered pre-#1457, and (c) composite-insight titles with
embedded figures unregistered pre-#1458 — run through `verifyCitations`
at each of the three fix points to show the recovery-rate progression
(0% → partial → fuller coverage) rather than a single before/after
snapshot. This would also serve as the regression guard for the
signed-positive-title edge case Greptile flagged as unresolved at #1458's
merge.

## Eval candidate

Yes. Per extension §26-29, this is exactly the kind of "evidence
faithfulness" and "factuality" dimension a Promptfoo eval case should
track separately from a composite score. Eval case: given a prompt whose
facts block, round-context values, and injected composite-insight titles
contain N legitimate numeric claims, assert `compose()`'s output — when it
cites any of those N figures — is **not** discarded, and separately assert
that a fabricated figure **is** still discarded (the negative case #1457
explicitly protected by not loosening the verifier). Tracking this as its
own eval dimension would have made the 08-16/08-17/08-18 chain of fixes
visible as a single regression trend rather than three independent PRs.
(Eval-candidate assessment recorded 2026-08-21, this backfill's authoring
date; no eval case implemented as of this date.)
