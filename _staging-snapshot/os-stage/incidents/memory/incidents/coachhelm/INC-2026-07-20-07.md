# INC-2026-07-20-07 — The Triage Desk ranked on the insert batch, not on when content was actually computed, and systematically demoted the freshest insights to zero

- **id:** INC-2026-07-20-07
- **feature_id:** coach_intelligence_triage / coachhelm (registry keys: `coach_intelligence_triage`, `coachhelm_ai`; code: `src/lib/coachhelm/v2/signal-groups.ts` (`ageDaysFromCreatedAt`), `src/lib/coachhelm/v2/signal-grouping.ts` (`recencyBonus`, `attentionScore`), Triage Desk components: `BriefBand`, `SignalDossier`, `SignalQueue`, `SignalRow`, `TeamSignalSummary`, `EffectivenessScoreboard`)
- **first_seen:** 2026-07-20T20:11:59-04:00 / 2026-07-21T00:11:59Z (commit `f2469655`, "ship CoachHelm triage workspace" — the recency/ranking logic that used `created_at` as a computation-time proxy shipped with the Triage Desk itself)
- **resolved:** 2026-08-15T23:24:14-04:00 / 2026-08-16T03:24:14Z (commit `65bde874a`, PR #1449 opened 2026-08-16T02:34:04Z, closed 2026-08-16T03:24:15Z — merged same session it was opened)
- **severity:** MEDIUM-HIGH (the ranking consequence was the *inverse* of the intended behavior — not neutral noise, but a systematic penalty on exactly the content coaches most needed to see first)
- **classification:** BEHAVIORAL_REGRESSION (primary — the surface's core sort order was backwards) / AI_QUALITY_REGRESSION (secondary — the evidence panel gap meant coaches acted on insights without seeing the sample size behind the claim)
- **status:** resolved

## Summary

Insights upsert by `signature`, so a row first created in June and
recomputed every morning since still carries its **original** `created_at`
— 68% of live rows were "born" in June by this measure, regardless of how
recently their content actually changed. `created_at` drove four things at
once through `ageDaysFromCreatedAt`: the rendered `"{n}d ago"` text, the
"new" filter (`ageDays <= 7`), the BriefBand "new this week" counter, and —
critically — the ranking itself, where `recencyBonus()` awarded +3/+2/+1
for content aged ≤1/≤3/≤7 days into `attentionScore`. Because genuinely
fresh content still carries a June `created_at`, **every actually-fresh
insight scored zero recency bonus** — the ranking term systematically
demoted the content it was designed to promote. Observed live on the Triage
Desk: "2 URGENT · 0 NEW THIS WEEK · 7 PLAYERS FLAGGED" while 60 rows had
been recomputed in the previous hour and 188 in the previous 36 hours —
not a data drought, a mislabeled one.

## Root cause (verified)

`created_at` on an upsert-by-signature row means "when this row was first
inserted," not "when its content was last computed." The codebase had no
separate `content_generated_at` column, so every consumer that wanted
"how fresh is this" reached for the only timestamp available and got the
wrong one. `updated_at` was considered and deliberately **not** substituted:
a DB trigger (`update_golf_coach_insights_updated_at`) bumps it on *any*
row update, and `insight-management.ts` writes `dismissed`,
`acknowledged_at`, and `lifecycle_state` transitions through the same
table — ranking by `updated_at` would have promoted an insight *because a
coach just dismissed it*, a different and arguably worse bug.

## Three defects, one root

1. **The Triage Desk said nothing was new while everything changed** — the
   ranking, filter, counter, and rendered age all shared the same broken
   proxy, described above.
2. **The surface where coaches decide showed the least evidence.**
   `EvidencePanel` (sample size, window, benchmark, stroke impact — not
   lossy even in compact mode) was mounted on individual insight cards but
   **nowhere** in the Triage Desk itself: zero instances across
   `BriefBand`, `SignalDossier`, `SignalQueue`, `SignalRow`,
   `TeamSignalSummary`, `TriageDesk`, `EffectivenessScoreboard`. A coach
   choosing what to act on from the primary triage surface could not see
   the sample size behind any claim.
3. **Archived insights had no recorded cause** (per the fix's own PR
   description; not independently re-verified in the sources reviewed for
   this backfill beyond the PR's own claim).

## User impact

Coaches using the primary Triage Desk surface saw a "what's new" signal
that was backwards for the majority of live content, and made
act/don't-act decisions without the sample-size context available
elsewhere in the product. This is a trust-surface defect on the tool
coaches were meant to check first each session.

## Repair

- `created_at`-based age display and the "new" filter are removed rather
  than re-pointed; the recency term in `attentionScore` is **neutralized
  to a uniform 0** rather than substituted for `updated_at`, on the
  explicit reasoning that a uniform 0 is truthful while +3 for an insert
  batch is not. A real recency term requires an explicit
  `content_generated_at` column — a migration, deliberately **not**
  included in this fix.
- `?filter=new` degrades to `all` rather than rendering an empty queue, so
  existing bookmarked/shared links don't silently show nothing.
- `EvidencePanel` is now mounted in `SignalRow`/`SignalDossier` and
  `HubInsightSignalCard`, which required plumbing `evidence` into the
  Triage select query (it wasn't selected at all before). Patterns that
  have no evidence render nothing rather than an empty shell, inheriting
  the panel's existing "too few to read reliably" honesty rather than the
  hand-rolled versions bypassing it.

## Recurrence risk

**A real recency term for the Triage Desk does not exist as of
2026-08-16T03:24:14Z (this fix), nor was it independently re-checked as of
2026-08-21** (this backfill's review date). The neutralization to 0
removes the *false* signal but does not
restore a *true* one — coaches lost "new" as a usable ranking/filter
dimension entirely until a `content_generated_at` column is added and
wired through. This is an intentional, disclosed tradeoff, not a hidden
gap, but it means the surface currently under-serves "show me what changed
recently" as a use case.

## Invariant candidate

Yes — a structural check that no ranking, filter, or display term reads
`created_at` on an upsert-by-signature table as a proxy for "content
freshness." This is a naming/schema-design class of bug (the column name
implies something the upsert semantics don't guarantee) worth a repo-wide
grep-based check (ast-grep pattern) rather than a runtime SQL invariant,
since the defect is in code logic, not in production data shape.

## Replay candidate

Yes — cheap. Fixture: a synthetic insight row with an old `created_at` but
representing content recomputed "today" (i.e., its signature was
re-upserted), run through `ageDaysFromCreatedAt` and `recencyBonus` pre-fix
(asserts a stale age reading and zero recency bonus despite being fresh)
and post-fix (asserts the recency term is uniformly 0, not falsely
promoting or demoting).

## Eval candidate

Not directly an LLM-generation defect — this is a ranking/display logic
bug in the deterministic triage layer, not the CoachHelm LLM composition
layer. No Promptfoo eval case applies. It is adjacent to AI-quality work
in the sense that coaches' trust in *any* CoachHelm surface (LLM-generated
or not) depends on surfaces like this reporting honestly, which is worth
noting for anyone designing an eval rubric's "actionability" or
"role appropriateness" dimensions per extension §26-29 — a rubric that only
checks LLM output text would not have caught this class of defect at all,
since the bug was entirely in deterministic ranking code downstream of
correct LLM/pattern output. (Eval-candidate assessment recorded 2026-08-21,
this backfill's authoring date; no eval case implemented as of this date.)
