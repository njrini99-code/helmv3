# INC-2026-08-17-03 — Team-level CoachHelm insights never existed: 21 runs, 1,343 insights written, zero team-scoped

- **id:** INC-2026-08-17-03
- **feature_id:** coachhelm (registry key: `coachhelm_ai`; code: `insights.ts`, `CrossLearner.buildGlobalPatternLibrary`)
- **first_seen:** 2026-02-05 (the team-insight writer code was committed and never worked; see Root cause) — **discovered** 2026-08-17
- **resolved_at:** 2026-08-18 04:49:55 UTC (fixed via a re-architecture, not a bug patch — see Repair)
- **severity:** MEDIUM
- **classification:** FUNCTIONAL_FAILURE (primary) / TELEMETRY_DEFECT (secondary — the failure was wrapped in a silent try/catch with no corresponding `admin_events` row found)
- **status:** resolved (by design change, not by making the original code path work)

## Summary

`golf_coach_insights` had 608 rows and not one with `player_id IS NULL` (the marker for a team-level insight). The writer, `generateTeamInsights`, was correct code that had existed since 2026-02-05 and had run 21 times against qualifying data (1,343 insights written in total, zero team-scoped) with no error ever surfacing. Investigation checked every downstream gate that could plausibly reject a team row — schema nullability, the signature builder, the upsert's null-player-id branch — and found all of them correctly handled. The actual failure was inside `CrossLearner.buildGlobalPatternLibrary`, wrapped in a `try/catch` that logged and continued, silently, for over five months.

## Root cause (verified)

Two independent defects were found in the cross-learner while diagnosing the silent failure, both worth recording on their own:

1. **"Team Strength" was structurally dead code.** The aggregate impact was computed as `Math.abs(p.strokeImpact)` averaged across a group — an absolute value, always ≥ 0 — and its only consumer then checked `averageImpact < 0` ("negative stroke impact = good"), a condition that can never be true given the input. Every team pattern would have been framed as a weakness, never a strength, had the writer ever succeeded.
2. **A key mismatch that would have zeroed every combined-strokes figure.** The insight feed read `metadata.strokes_impact`, a key present on 0 of 501 active insights; the generators actually write to `evidence`. This was fixed separately (`6d2ea74b7`, same series) and is a prerequisite for the team-signal fix below to show real numbers rather than zeros.

## User impact

- Coaches never saw a team-level rollup insight in production, on any team, across the entire life of the feature (since 2026-02-05) — five and a half months of a shipped, apparently-working feature (21 successful cron runs, no errors) that produced nothing for its intended purpose.
- No corresponding `admin_events` row was found for the silent failure — though the investigation notes retention may not reach back to July, so absence of evidence is explicitly recorded as unknown, not as proof nothing was ever logged.

## Repair

Fixed 2026-08-18 04:49:55 UTC via `77c49aec8` + `256a71a4d`, but **not** by making `generateTeamInsights`'s write path work. Re-measured the same day: still 0 of 615 rows team-scoped — **confirmed by design, not a regression.** The fix instead:

- **Synthesizes team-level signals at read time**, not write time. `groupSignals` already bucketed insights by `playerId ?? '__team__'` and pinned the team bucket first — the display surface existed and was simply never fed. No new table, no migration, no cron: a team card now derives its content from per-player signals already fetched, and by construction can only cite leaks the coach could also open individually below it.
- **Rejected the "obvious" definition of a team signal** ("several players share this insight") as noise, backed by data: all 12 Guilford players carried an `approach_proximity_175_plus_ft` insight because the generator emits one per player regardless of whether it found a real leak — shared *presence* just measures generator coverage, not a real team-level finding. A test pins that this case emits nothing.
- **Defined the real signal as shared recoverable strokes** — e.g., Guilford's `practice_tournament_delta` affecting 4 players for a combined 18.01 strokes/round.
- **Follow-up bug caught in review and fixed same-series (`256a71a4d`):** the new roll-ups were initially typed `kind: 'insight'`, which double-counted them in `TeamSignalSummary` (three leaks worth 4.5 strokes rendered as "4 live | 9.0 est. strokes") and exposed Mark-reviewed/Dismiss controls that could not function against a synthetic `team:<metric>` id with no backing row.

## Verification evidence

- Re-measured 2026-08-18 against production: 0 of 615 rows team-scoped, confirming the original report's number was real and stable (up slightly from 608, consistent with normal insight-generation volume, not with the fix having started writing rows — which it deliberately does not).
- The `metadata.strokes_impact` vs. `evidence` key mismatch was confirmed against production: 0 of 501 active insights carried the read key, meaning every "combined strokes" figure would have rendered zero before `6d2ea74b7` landed in the same series.
