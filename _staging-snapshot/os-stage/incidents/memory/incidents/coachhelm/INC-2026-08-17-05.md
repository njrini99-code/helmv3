# INC-2026-08-17-05 — Three Genome/causal-engine dimensions computed statistically wrong values: scrambling, miss-side bias, and single-effect causality

- **id:** INC-2026-08-17-05
- **feature_id:** coachhelm (registry key: `coachhelm_ai`; code: `src/lib/coachhelm/v3/genome/dimensions/*.ts`, `src/lib/coachhelm/v3/genome/causal-engine.ts`)
- **first_seen:** 2026-08-17 (all three issues filed same day; the underlying formulas predate discovery — exact onset not established for any of the three)
- **resolved_at:** #1499 and #1500 closed 2026-08-21; #1501 closed 2026-08-21 (fix landed 2026-08-18/19 per commit dates, extended further the following day)
- **severity:** MEDIUM
- **classification:** AI_QUALITY_REGRESSION (primary — all three are the Genome/causal layer telling coaches something statistically false, not a crash or outage)
- **status:** resolved

## Summary

Three independent, distinct-root-cause defects in the Genome/causal-engine dimension calculations, discovered and fixed in the same investigation window but **not the same bug** — grouped in this one record because they share a class (statistical formula errors in the same subsystem, found and fixed together) rather than a shared mechanism. This is a deliberate dedupe judgment call: each has its own commit, its own test, and would stand as three genuinely separate incidents by strict root-cause criteria; they are combined here for navigability given how tightly the investigations overlapped.

1. **#1499 — Scrambling is a proximity proxy, not scrambling.** The Genome's scrambling dimension called 14 players "Wizard" when the canonical golf definition would have called them "Leaky." Root cause: the formula used a proximity proxy instead of the standard definition (`gir === false` filtered to `score <= par`).
2. **#1500 — Miss-side bias reads a 2-value side off an 8-value compass.** The miss-direction data model has 8 compass values (`short_left`/`long_left`/`short_right`/`long_right`/bare `short`/`long`/etc.), but the bias calculation only handled 2, dropping 58% of the signal and inverting the reported bias for some players.
3. **#1501 — The causal engine only ever related a scoring component to the score itself.** Out of 5,641 computed relationships, there were only 4 distinct causes and exactly **one** effect (score) — the engine could never surface a relationship between two non-score components (e.g., GIR affecting putts), which is a large part of what a "causal engine" should be capable of finding.

## Root cause (verified)

- **#1499:** `computeScramblingRate` used a distance/proximity heuristic rather than the canonical scrambling definition. Fixed by replacing it with `gir === false` filtered to `score <= par`, and recalibrating the Wizard/Reliable/Leaky cutoffs (`WIZARD_AT`, `RELIABLE_AT`) against the real cohort distribution measured from the corrected formula.
- **#1500:** the miss-side mapper handled only 2 of the 8 possible compass values the data model actually stores, silently dropping or misclassifying the rest.
- **#1501:** the causal engine's relationship-building logic was structurally scoped to always name `score` as the effect side of any relationship, never allowing two non-score components to be related to each other.

## User impact

- **#1499:** 14 players were told, in a coaching product whose entire premise is trustworthy per-player analysis, that a weakness (leaky scrambling) was a strength (wizard-level scrambling) — the exact inversion a coach would act on in the wrong direction.
- **#1500:** miss-side bias, a core diagnostic ("this player misses left" / "this player misses right"), was wrong or incomplete for the majority of miss events (58% of signal dropped) and inverted for some players — again, actionable coaching guidance pointing the wrong way.
- **#1501:** the causal engine's real analytical capability was far narrower than its output volume suggested — 5,641 relationships sounds substantial, but all of them were structurally the same shape (component → score), so genuinely useful causal chains (e.g., "your GIR rate is driving your three-putt rate") were never discoverable at all.
- **Stale-value correction applied across all three:** a companion commit (`3eeebcf47`) retires pre-fix stored values to "uncomputed" for genomes that predate the formula fixes and won't be recomputed soon (need ≥8 completed rounds in 90 days — only 8 of 28 eligible players cleared that bar at investigation time), rather than leaving incorrect cached values visible under a now-correct label.

## Repair

- **#1499:** `b387973a3` — canonical GIR-based scrambling formula, recalibrated cutoffs against the real cohort's measured p75/p25.
- **#1500:** `12561d5db` — `sideOf()` mapper added, covering all 8 compass values (`short_left`/`long_left` → left, `short_right`/`long_right` → right, bare `short`/`long` → excluded).
- **#1501:** `80472667a`, extended the following day with a second research-backed hypothesis (`total_gir → total_putts`) added at `causal-engine.ts:222-231`, specifically addressing a putts-per-round confound the issue itself had flagged.
- **Shared cleanup, `3eeebcf47`:** retires stale pre-fix values in `loadGenome`/`loadGenomes` to "uncomputed" rather than silently continuing to show them under the corrected label — applied to ~40 of 48 active-roster genomes for the scrambling/miss-side fixes.
- **Explicitly out of scope, by owner decision, not an oversight:** #1500's issue also asked for a "calibration audit" of the other Genome dimensions (`par3_proficiency`, `driver_usage`, `back_nine_delta`, `pressure_delta`). That audit found **no correctness bug**, only that absolute-golf-referenced thresholds barely discriminate against a college-team population — recorded as a product decision for a pending Genome redesign, not fixed here.

## Invariant candidate

Partial. These are formula-correctness bugs in application code, not data-state violations a read-only SQL check can directly catch. The closer fit is the golden-path/eval layer the extension proposes for CoachHelm (§26-29, "CoachHelm AI evaluation memory") — a periodic check that a small set of known-correct worked examples (e.g., a synthetic player with known GIR/score data) produces the expected scrambling classification, miss-side bias, and causal relationships, would have caught all three of these as regressions if it had existed and been run against the pre-fix code.

## Replay candidate

Yes, moderate value, for #1499 and #1500 specifically — both have a clean, deterministic input→output contract (a shot/round record → a classification) that would make a small eval-style fixture cheap to build and durable as a regression guard against the specific formulas. #1501 is lower priority for a replay fixture given it's more of a capability gap (the engine COULD find more relationships) than a strict correctness bug with a clear pass/fail before/after state.

## Status

**Resolved**, all three. The four-dimension calibration-audit finding remains open as a named product-quality gap, not a bug.
