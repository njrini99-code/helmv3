## Summary

`miss_direction` is an **eight-value compass** in production:

```
left, right, short, long, short_left, short_right, long_left, long_right
```

`miss_side_bias` filtered on the bare strings `'left'` / `'right'` only.
Every compound value — `short_left`, `long_right`, and the other four — was
silently discarded even though each still names a side as clearly as the
bare value does. Filed the same day as the scrambling proxy bug
(`INC-2026-05-25-03`), found by the same "does the Genome agree with a
plainer read of the data" method, on the second genome dimension checked.

## Root cause (verified)

A two-value equality/inclusion filter (`=== 'left'` / `=== 'right'`, or
equivalent) was written against a field whose real domain has eight
values, six of which are compound directional strings. The filter was
correct for the two values it recognized and silently wrong — not
erroring, just dropping the row — for the other six, which is the same
silent-discard shape as the citation-verifier bugs in this feature area
(`INC-2026-08-16-09`): a filter or verifier that fails closed on inputs it
was never taught to recognize, with no logged signal that anything was
skipped.

## Measured (90-day window, 2026-08-17)

Before the fix, `miss_side_bias` had a computed value for only **3
players**. Adding compound-direction coverage raised that to **13** — the
2-value filter had suppressed roughly 77% of the players who actually had
enough directional data to support a verdict.

## Worse than sparse: the subsample inverts

The 3 players who *did* clear the pre-fix filter were not a random,
unbiased subsample of the full population — players whose misses were
predominantly compound-directional (e.g., mostly `short_left` rather than
bare `left`) were exactly the players the filter was blind to. For at
least one player in the reviewed evidence, the bare-value-only reading and
the full-compass reading pointed at **opposite** sides. A coach reading
"Symmetric" (no data / no lean) for a player who is in fact heavily biased
toward one side was told nothing was wrong when something was.

## Repair

Commit `12561d5db`, 2026-08-17T18:23:38Z:

- The filter/classifier was rewritten to bucket all eight `miss_direction`
  values onto a left/right axis (each compound value contributes to the
  side its compound name says: `short_left`/`long_left` → left,
  `short_left`/`long_right` → right), rather than matching only the two
  bare strings.

Commit `3eeebcf47`, 2026-08-18T04:49:12Z (next-day follow-up):

- Addressed a second-order effect: some displayed readings were still
  showing values computed by the pre-fix formula until they recomputed,
  which this commit stopped from surfacing stale/incorrect readings ahead
  of recomputation.

## Invariant candidate

Yes — a schema-domain-coverage check: any classifier that pattern-matches
on a categorical column should be asserted, in a test or a runtime check,
to cover every value the column's real domain contains (here:
`miss_direction`'s 8 compass values), not just the values a developer
happened to think of. This generalizes past this one dimension to any
future genome/pattern classifier reading a compound-value enum.

## Replay candidate

Yes — cheap. Fixture: a synthetic player whose misses are 80% compound

pre-fix filter (predicts near-zero signal / Symmetric) and the post-fix
bucketed classifier (predicts a real left-leaning bias). This is a
self-contained unit-level replay, no production data needed.
