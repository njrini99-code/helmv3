## Summary

The LLM-generated "hero narrative" feature had 186 recorded calls, then dropped to zero, with nothing in the system surfacing that the feature had gone silent. Root cause: a prior redesign of the player CoachHelm surface orphaned the component cluster that rendered it (`FairwayPlayerCoachHelm`/`HeroNarrativeCard`/`FocusAreasGrid`), leaving the generation code live and reachable in principle but with no UI route ever calling it.

## Root cause (verified)

Not independently re-derived beyond the fix's own framing: a redesign replaced the player CoachHelm surface without carrying the hero-narrative-consuming components forward, leaving them orphaned (unreferenced from any route) rather than explicitly retired. The generation logic itself kept working; it simply had no caller left.

## User impact

- Players stopped receiving hero-narrative content entirely from the moment of the redesign, with no error, no empty state explaining the gap, and no telemetry catching the call-volume drop from 186 to 0 — discovered only because someone happened to look for one.
- Duration of the gap between the redesign and discovery (2026-08-18) is not established in the sources reviewed for this backfill.

## Repair

Resolved by `a259fa296` (2026-08-18, ~4.5 hours after the issue was filed) — **deliberately deleted** the orphaned `FairwayPlayerCoachHelm`/`HeroNarrativeCard`/`FocusAreasGrid` cluster rather than reconnecting it to a live route. The commit message (per the closing comment) explicitly frames this as addressing the dead-code state on purpose, rather than leaving it silently orphaned indefinitely — i.e., the resolution was "stop pretending this is live" rather than "make it live again," which is a product decision as much as a bug fix and is recorded here as such rather than implied to be a restoration of the original feature.
