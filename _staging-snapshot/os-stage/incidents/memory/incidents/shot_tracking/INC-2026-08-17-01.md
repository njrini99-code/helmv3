# INC-2026-08-17-01 — Four overlapping RLS policies on `golf_shots` made the shot-driver query 580x slower and silently dropped insights' root-cause layer

- **id:** INC-2026-08-17-01
- **feature_id:** shot_tracking (registry key: `shot_tracking`; also read by `coachhelm_ai`'s insight-delivery path)
- **first_seen:** 2026-08-17 (issue #1490 created; the underlying policy shape traces to at least 2026-07-28, see Recurrence risk)
- **resolved_at:** 2026-08-18 04:59:57 UTC (issue #1490 closed COMPLETED, migration applied and verified in production same day)
- **severity:** HIGH
- **classification:** PERFORMANCE_REGRESSION (primary) / FUNCTIONAL_FAILURE (secondary — the timeout caused a real feature, shot-driver root-cause insights, to silently degrade)
- **status:** resolved

## Summary

`fetchShotDriversByCategory` — the query that turns a generic insight ("your approach play is weak") into a specific, actionable one ("you miss short and right from 175+ yards from the rough") — shared a 5-second best-effort budget across a paginated walk of a player's shots. For any of the 7-of-42 players carrying more than 1,000 shots (max 1,302), a second page was required, and the query cost tipped the walk over budget. Root cause, measured directly: the identical query against `golf_shots` ran in **4.1ms** as service-role (RLS bypassed, 187 buffers) versus **2,387ms** as an authenticated coach (RLS on, 263,519 buffers) — a **580x** difference. Production had logged 35 aborts of exactly this query before the fix.

## Root cause (verified)

`golf_shots` carried four overlapping permissive SELECT policies, OR'd together, ending in a correlated `EXISTS`. A correlated subquery cannot be hashed, so Postgres evaluates it per row rather than pushing the `round_id IN (...)` predicate down through an index. The plan showed `SubPlan 85` (a `golf_rounds` lookup) running **13,233 times** — once per candidate shot — for a query that should have needed an index-only scan. This was diagnosed independently of, but is the same defect class as, a fix that had landed three weeks earlier (`20260728030000_shot_detail_rls_correlated.sql`) for the *detail* tables (`putt_details`, `approach_miss_details`) — that migration explicitly routed those two tables around the same correlated-EXISTS shape but left `golf_shots`' own four policies standing, and its own header predicted the cost would scale with the whole database, not the requested rows. This incident is the follow-through the July migration deferred.

Ruled out during investigation: sort-key forcing a non-index-using plan (`.order('id')`) — tested and found to account for only ~13% of the cost (2,387ms → 2,075ms with a covering sort key), noise against the 580x problem; the per-row policy evaluation dominates regardless of sort order.

## User impact

- Any coach viewing insight-delivery for a high-shot-volume player (7 of 42 measured, up to 1,302 shots) had a real risk of the root-cause layer silently disappearing — `fetchShotDriversByCategory` returns `undefined` on abort and the caller continues without shot drivers, no error surfaced to the coach.
- Directly named as "the mechanism behind 'insights are generic and not root-cause'" — a long-standing product complaint given a confirmed, specific technical cause here.
- 35 production abort events logged for this exact query before the fix (count as measured at investigation time, not necessarily the full lifetime total).

## Repair

- Migration written and committed 2026-08-17 12:28:32 UTC (`2270e43cb`), deliberately **not applied immediately** — RLS changes on the shared production database were treated as requiring explicit owner sign-off before applying, per this repo's stated Supabase caution.
- A regression guard followed in `0c8abbcb8` (same day).
- Applied and verified in production **2026-08-18 04:59:57 UTC**: `golf_shots` reduced from 4 overlapping permissive SELECT policies to 2 (`golf_shots_select`, `admin_read_all`), restoring `Index Cond: (round_id = golf_rounds.id)`.
- **Swept the rest of the schema for the same defect shape** (correlated `EXISTS`, not merely "more than one permissive policy" — the discriminator is stated explicitly): `golf_coach_insights` (4 policies, no correlated EXISTS, 608 rows) measured fine at 5.6ms and was confirmed NOT to need the same fix — a real negative check, not an assumption.
