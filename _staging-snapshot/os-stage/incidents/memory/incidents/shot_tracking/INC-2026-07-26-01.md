## Summary

`insight-delivery.fetchShotDriversByCategory` was failing in production
repeatedly with `AbortError` against its own 5-second best-effort budget: 40
occurrences between 2026-07-26 and 2026-07-29 — the single largest
warning-severity fingerprint in the feed at the time. Each failure meant a
player silently lost shot-driver enrichment on their CoachHelm insight
themes, with no error surfaced to the user.

Issue #1172 was filed to measure a **plausible but, on further
investigation, wrong** hypothesis: that `golf_shots`'s four overlapping
permissive SELECT policies (`admin_read_all`, `golf_shots_select`,
`golf_shots_select_own`, `golf_shots_select_team`) were the cost driver,
since Postgres ORs all permissive policies together and evaluates all four
on every read.

**That hypothesis was investigated and explicitly refuted by the same
author**, in a follow-up comment on the same issue, citing a comment already
present in `insight-delivery.ts` itself: a direct, unordered
`golf_rounds (player_id, status='completed') LIMIT 200` joined to
`golf_shots (round_id IN …) LIMIT 25000` measured at **68ms**, an Index Only
Scan on `idx_golf_shots_round_id_covering` — fast, not the bottleneck. The
actual cost was traced to RLS on the two **embedded** tables in the same
query: `putt_details_select_team` and `approach_miss_details_select_team`
are six- and seven-table joins that **materialize every shot id visible to
the caller across their whole organization**, uncorrelated to the ≤200
rounds actually being requested. One such call costs ~100-200ms; several
running concurrently, each rebuilding an org-wide id set from scratch, is
what crosses the 5-second abort budget.

## Root cause (as verified by the retraction comment, dated ~2026-08-03, exact time unknown — within this window)

**Not** `golf_shots`'s own SELECT policies — that hypothesis was raised,
measured, and explicitly retracted by the same investigator on the same
issue thread. The actual cost sits in the RLS policies on `putt_details`
and `approach_miss_details`, which are joined as embedded resources inside
the same query. `putt_details_select_team` and `approach_miss_details_select_team`
are six/seven-table joins that materialize the full set of shot ids visible
to the caller across their **entire organization**, with no correlation to
the specific ≤200 rounds the outer query actually asked for. Each embedded
join re-derives that org-wide set from scratch; several concurrent callers
compound the cost, crossing the 5-second best-effort budget.
