## Summary

A dedicated postmortem (`docs/audits/BASEBALLHELM_SHELL_ROUTE_POSTMORTEM_2026-06-30.md`) documents how BaseballHelm accumulated a large backlog of shell/route/auth/stats defects through 2026-06: PRs #344 (1,009 files / +223,504 lines), #335 (316 files / +30,638), and #356 (507 files / +151,480, still open at postmortem time) each exceeded both the external review bot's 100-file ceiling and CodeRabbit's 150-file ceiling, meaning they were never actually reviewed by either automated gate. A systematic audit against `BASEBALLHELM_CANONICAL_SPEC.md` on 2026-06-29/30 then catalogued the resulting defects as ~150 GitHub issues (#349–#520 range, minus a handful pre-existing), fixed almost entirely in one large remediation PR (#421) plus three follow-ups the same day.

## Root cause (verified, from the postmortem's Five Whys)

**#1 — PROXIMATE: Oversized, unreviewable PRs.** Three PRs each exceeded both automated review bots' hard file-count ceilings, so they landed on `main` with zero effective automated review coverage — not inferred from size, confirmed directly against the bots' stated limits.

**Contributing — Parallel-swarm duplication.** Multiple concurrent build efforts authored overlapping/duplicate implementations of the same surfaces (nav layer, `helm_lifting_*` vs `baseball_lift_*` tables) without a shared source of truth, producing migration timestamp collisions (`20260624001400`, `20260630170248`) once any landed.

**Contributing — Knowledge gap: no baseball source-of-truth.** `memory/registry.yml` (added 2026-05-27) carried 259 golf references and 0 baseball references at this point; CLAUDE.md's own routing table still read "Baseball features: No deep reference yet" unchanged since 2026-02-13 — the same commit that built out the full golf knowledge stack. Every agent session building baseball features had to re-derive the architecture from raw source with no persisted map of what already existed.

**Contributing — Governance: unenforced branch protection.** Branch protection was documented on 2026-05-17 but not mechanically verified against the live GitHub API, leaving a gap between documented and enforced policy.

**Contributing — Tooling: rate-limit secondary damage.** The volume of oversized-PR review activity exhausted CodeRabbit's account-level quota, causing even a properly-sized PR (#341, 34 files/1 commit) to be skipped via rate-limiting rather than file-count limiting — the mega-PR problem degraded review coverage for smaller, well-formed PRs too.

## User impact

Real, if unquantified in user-sessions: the ~150 catalogued defects included live authorization bugs (e.g. #472 — insight dismiss/feedback comparing `coach_id` to `auth.user.id` rather than a mapped coach identity; #501 — staff capability grants uncapped by the inviter's own permissions; #510 — `approveAiOutput` bypassing player-visible AI policy), stats-correctness bugs (#434 — innings pitched summed as base-10 decimals instead of outs; #436 — OBP/SLG/OPS not computed in legacy aggregate recalculation), and broken core flows (#440 — join-code confirmations bypassing the canonical join path; #442 — camp capacity not enforced atomically, allowing overbooking). Given BaseballHelm was actively being built/onboarded through this period, the honest read is these were live production defects for however long each contributing PR had already been merged before the 06-29/30 audit caught them — not merely pre-launch findings, since PR #344 etc. had already shipped to `main`.

## Repair

- PR #421 (2026-06-30) — mass remediation closing 146 of the ~150 catalogued issues.
- PR #517 + follow-ups #519, #520 (2026-06-30) — RLS hardening on phase-1 tables and practice block/attendance policies, explicitly framed as completing what #421 didn't fully close.
- Postmortem §7 "Prevention" proposes 5 concrete measures: hard PR-size CI gate (~400 lines/~20 files) that blocks merge (not just comments); one-surface-per-PR with a ban on "snapshot(working-tree)" squash commits; serialized migration-timestamp ownership with a per-PR Squawk gate; building the baseball source-of-truth (`memory/registry.yml`/`memory/context/` parity with golf) and promoting `nav-manifest.ts` from passive to enforced; and branch protection verified against the live API on a schedule, not just documented.

## Recurrence risk

**Confirmed partially recurred.** The postmortem's own prevention list is the best evidence: item 4 (baseball source-of-truth, `knowledge:map`/`knowledge:context` wired into CI) was still an open gap as of later audits in this repo (see `docs/REPO_MAP.md`'s ongoing golf-vs-baseball documentation-parity commentary). The size-ceiling CI gate proposed in item 1 is not confirmed as landed and enforced from evidence gathered in this pass — worth a follow-up check against `.github/workflows/*.yml` for an actual PR-size blocking check.

## Invariant candidate

Not a single SQL invariant — this is a process/governance failure. The closest deterministic check: a CI gate on PR file-count/line-count that fails (not just comments) above the review bots' actual ceilings, verified to actually be wired in as a **required** status check (not an advisory one) — the same "documented vs. enforced" gap that let the underlying branch-protection failure recur elsewhere in this repo's history (see CLAUDE.md's own note about phantom required checks fixed 2026-08-19).

## Replay candidate

No conventional replay fixture — this is a repo-governance incident, not an application code defect with a reproducible input/output shape. The individual defects it produced (auth bugs, stats bugs) are each independently replay-candidates in their own right if any remain unverified by regression tests; that audit is out of scope for this incident record and would need per-issue follow-up.

## Status

Resolved (the catalogued defects were fixed). Prevention measures: partially adopted, not fully verified as landed — see Recurrence risk.
