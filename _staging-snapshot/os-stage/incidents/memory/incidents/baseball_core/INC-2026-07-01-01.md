## Summary

Three related-but-distinct schema-drift defects surfaced within 48 hours, all against the same shared Supabase project, all root-caused and closed in `docs/audits/SUPABASE_DRIFT_REPORT_2026-07-03.md`: (#651) 12 columns queried by code were reported missing in prod across `baseball_teams`, `baseball_practice_effectiveness_reviews`, `baseball_stat_sources`, `baseball_fielding_events`, `baseball_baserunning_events`, `baseball_catching_events`, `baseball_plate_appearances`, `baseball_decision_log`; (#728) the live body of `recalculate_baseball_season_stats` had drifted to reference a stale column `b.so`, breaking all callers; (#732) `public.rate_limits` relation and its `expires_at` column were reported missing.

## Root cause (verified)

For #651: verified via direct `information_schema.columns` query that all 12 named columns **do exist** in production today, with corresponding migrations both on disk and in the remote ledger (`baseball_651_column_reconcile`, `baseball_651_settings_os_reconcile`) — the drift report notes a local/remote migration **version-number mismatch** is a separate, cosmetic pattern, not evidence of missing content, and was the likely source of the original false-missing report. For #728: the function body had genuinely drifted to a stale column reference and was fixed via hotfix same-window. For #732: report notes "no first-party function reference found" — meaning the reported missing relation was not actually referenced by any first-party code path, downgrading its urgency.

## User impact

#651 and #728 represent real runtime errors on affected code paths (queries against columns/functions that didn't match the live schema) for baseball coaches using the affected surfaces (practice-effectiveness reviews, stat sources, season-stats recalculation) between the drift's introduction and the fix. #732 had no confirmed live impact since no first-party caller was found.

## Repair

Migrations `baseball_651_column_reconcile` / `baseball_651_settings_os_reconcile` applied (local `20260702095900`/`20260703050000`, remote `20260702035814`/`20260703044143`). `recalculate_baseball_season_stats` corrected via same-window hotfix (#728 was filed as already-resolved, needing only a drift guard). #772's linked-lint findings (`can_manage_baseball_lift_group`, `baseball_accept_staff_invite`) separately re-verified clean — both function bodies correctly reference real columns (`email`, `invitee_name`, not a stale `invitee_email`).

## Verification evidence

Direct `information_schema.columns` queries for all 12 #651 columns, confirming presence with correct types. Migration ledger cross-referenced (local timestamp vs. remote-recorded timestamp) to distinguish "genuinely missing" from "recorded under a different version number."
