The page builds springs with the same physics as `lib/motion.ts` (ω = 2π / (1.2 × visualDuration), ζ = 1 − bounce) but ends the curve once it stays within 0.2% of its mark; the app's `chSpringCurve` ends it at 0.1%. ### `pour`: what to add

`src/clubhouse/lib/motion.ts`:

```ts
export const CH_SPRINGS = {
  smooth: { visualDuration: CH_DUR.base, bounce: 0 },
  settle: { visualDuration: CH_DUR.base, bounce: 0.1 },
  reveal: { visualDuration: CH_DUR.reveal, bounce: 0 },
  /** The quick chat panel pouring out of the Helm key (2026-10-31): a native sheet's settle, no bounce. */
  pour: { visualDuration: 0.42, bounce: 0 },
} as const;
export const CH_EASE_SHEET = [0.32, 0.72, 0, 1] as const;
```

Reduce Motion uses the existing `CH_FADE_MS` (180ms today, opacity only, `linear`); this lane adds no duration of its own.

`chSpring('pour')` then gives stiffness 155.42, damping 24.933, mass 1. `chSpringCurve('pour')` gives 742ms and the string below, generated exactly as the smooth token was (1/240s steps, cut within 0.1% of the mark, sampled `round(742 / 16) = 46` steps, 47 points). It reaches 50% at 135ms, 90% at 313ms, 99% at 533ms, and never passes 1.

The fallback where `linear()` is missing follows the smooth token's pattern (`--ch-ease` over the visual duration, 420ms). The page's own fallback is `EASE` over 680ms; only WebKit before 17.2 sees either. Extend `motion-physics.test` to pin `--ch-ease-spring-pour` to `chSpringCurve('pour').linear` the way it pins smooth. A WAAPI call must not pass a `linear()` string where it's unsupported: it throws. Guard with `CSS.supports('animation-timing-function', 'linear(0, 1)')`, as the page does at line 932.

## Rules for every row

- Animate `transform` and `opacity` only. Exceptions: the SVG `stroke-dashoffset` draws (step check, receipt check, Undo ring). Colour changes switch in one frame; where a fill fades in (the calendar cell, M-VISUAL-cal) it is a layer under the content whose opacity moves.
- **Put the curve where the keyframes are.** WAAPI's effect `easing` warps the whole effect, so on a three-keyframe move the middle `offset` lands at a point in eased progress, not in time; framer's `times` + `ease` puts the curve on each segment. The page no longer mixes the two: two-point moves carry their curve on the effect (`anim()`, line 943); multi-point moves set the effect to `linear` and put a curve on each keyframe (the press dips M-ASK-pick, M-TASK-settle, the seats in M-VISUAL-qual, M-LAND-msg; and M-FAIL); the close and the plan page are a transform effect plus a separate opacity effect (M-CLOSE, M-LAND-plan). Build these with `el.animate` as written, or framer `times` + per-segment `ease`, which now match. The one exception is the land flyer (M-LAND-cal): its arc is sampled into 21 keyframes and the `smooth` spring is the effect's easing, so the spring paces travel along the arc; build it with WAAPI as written. M-WON is CSS keyframes (per segment).
- Interruptible moves (panel open, close, retarget) run in script with WAAPI on refs, never on render: read the current value with the page's `hold()` (computed `transform` and `opacity`, read *before* cancelling), cancel, start from there. No framer `layout`, no `AnimatePresence` for the panel.
- Reduce Motion means Playwright `reducedMotion: 'reduce'` and iOS Settings > Accessibility > Motion > Reduce Motion (`useChMotionMode()` = `fade`): every move becomes an opacity crossfade of `CH_FADE_MS` (180ms today), `linear`, from its first frame's opacity to its last (the page's `anim()` reduce path), loops stop, nothing travels, scales or rotates (SHARED-6). Settings > Animations off (`[data-motion='off']`, mode `off`) is instant, as everywhere in the app.
- Delays in the task visual rows are the page's demo pacing. In the app each field moves when its data arrives, in the order the data arrives (AGENT_KIT ②: never a fake stagger). Durations and curves don't change.
- Haptics go through `src/clubhouse/lib/haptics.ts` `haptic()`. It is native only (Capacitor iOS shell, `@capacitor/haptics` ^8.0.2) and respects the user's haptics setting. This lane adds three: `press` (light impact) on the key, `success` on a receipt, `warning` on a failed write. Every other row is "none". Sound: none.
- Check: `node capture/capture.mjs --motion <M-ID>` records the design page (its Play button) and the app (`?qc=` state + `&play=`) at 390 wide, full motion and then Reduce Motion. `node capture/capture.mjs --motion <M-ID> --reduce` is the Reduce Motion clip alone once QC6 adds the flag. Frame times are ms after the trigger at 60fps; a row passes when the app frame shows the same state as the design frame within one frame (SHARED-12). T1 to T6 are the page's six in-page tests (`#motion-check`, `capture.mjs --motion-check`), ported to `e2e/clubhouse/quick-chat-motion.spec.ts` in QC6: **T1** close mid-open starts where the panel is; **T2** open mid-close starts where the panel is; **T3** open holds frame rate (at most one frame over 25ms); **T4** panel height fixed through a whole task; **T5** only transform and opacity animate (plus the Undo ring and the check strokes), counting script animations, CSS animation names and CSS transitions (`transitionrun`) inside the device; **T6** under Reduce Motion every move and every transition is opacity at `CH_FADE_MS` (180ms today) or less, over the close, open, `whole`, `plan` and `live` plays.
- Rows marked *new ID* record the clip named in brackets: capture.mjs's `MOTION` map gives each one its parent row's play and start state.

## Never animate (this lane)

- `height`, `width`, `max-height`, `top` / `left` / `right` / `bottom`, `margin`, `padding`, `grid-template-rows`, `flex-basis`: any layout property. The panel's height, width and position never change while it is open, and nothing inside it tweens a height (T4).
- `box-shadow`: the panel's two-layer shadow and lit edge, card shadows. The finish flash is opacity on a pseudo-element ring (M-WON).
- `filter` and `backdrop-filter` values: the glass blur(30px) saturate(180%) is fixed (the scrim has none); only their layers' transform and opacity move.
- Colour. The calendar cell's fill fades as an opacity layer (M-VISUAL-cal). Selected pills, the sent bubble, chip states, Send and Stop, seats, "Not set" ink and the primary's dim state switch in one frame.
- The green bar: its height, layout and title never move. The key slot stays 44pt; the live pill overlays the slot and grows left by scale, never pushing the title.
- Anything on page load, route change or state restore: the key renders at rest; a panel restored open shows at rest (the page's `openPanel(true)` is instant). No entrance staggers on load; the one stagger is M-CONTENT, on a tap.
- No count-ups: the folder count, "+N" and "Sending in 8s" are text swaps.
- No motion on re-render or data refresh: a streamed token, a refetch or reopening the panel never replays a row. Rows that arrived while the panel was closed render at rest when it opens.
- Scroll: only M-GROW's smooth scroll to the end; nothing scroll-linked inside the panel; nothing blurs or casts an animated shadow on scroll.
- No hover motion on desktop.
- Text never animates by letter except M-TYPE.

## Frame budget

- **Composited:** every `transform` and `opacity` move above, run through WAAPI (`el.animate`) on elements, not React state. Chromium runs these on the compositor; WebKit accelerates WAAPI transform and opacity too. `linear()` easings need iOS / Safari 17.2+ (guard as in the pour section).
- **Painted each frame (kept small and short):** the SVG stroke draws (16pt step check 240ms, 24pt receipt check 300ms, 22pt Undo ring for 8s), the caret blink, and typed text. Typed text reflows the bubble one line at a time as the draft wraps (the page does this; no animation on it). The title has a fixed one-line min-height, so typing it never moves the card.
- **The heavy part is the glass:** the panel (`backdrop-filter: blur(30px) saturate(180%)`) re-samples what's behind it on every frame it scales or fades. It animates only during M-OPEN, M-CLOSE and M-RETARGET, and while it does, nothing else starts except M-CONTENT, M-SCRIM and M-KEY-press. If T3 fails on a phone, report it with the device; don't drop the blur quietly. (Reduce Transparency already swaps the glass for solid in tokens.css 1204 to 1221.)
- **`will-change`:** set `transform, opacity` on `.qc` when M-OPEN, M-CLOSE or M-RETARGET starts and remove it in the move's finish and cancel handlers. Same for the land flyer and the plan page while they run (430 / 462ms) (both are removed nodes anyway). The step band keeps its CSS `will-change: transform` (it exists only while a step is active). Never permanent on the panel (a 382×700pt glass layer at 3x is several MB), cards, rows or the scroll container.
- **At most running at once:** open is 8 (panel transform, panel opacity, scrim, 3 parts, disc opacity and scale). The cal finish peaks at 9 (cell, dot, chip, flash, receipt row, disc, halo, check, ring). Budget: no more than 10 animations at once in the panel, and no more than 2 on backdrop-filter layers. Loops on top: 1 dot, 1 band, the skeleton bands of one card (8 at most, qualifier), the sweep or spinner, the wheel.
- **No layout reads inside a move:** read the origin, the flyer's rects and the held values once, before starting. Drop the page's two `offsetHeight` reads per append in `grow()` (line 1283) and its forced reflow to restart the flash (line 1615). The FLIP in M-ASK-fold reads two `offsetTop` values once, before its move starts: that is allowed.
- **Append-only turns:** memoise finished parts so a streamed token never re-renders, and so never restarts, an earlier row (SHARED-6).
