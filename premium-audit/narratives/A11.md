## Findings

**A11-001 (P1, SOURCE, ties G25)** — `useConnectionStatus` has no module-level dedup, so two
independent 30s polling loops run concurrently during round entry, each with its own
`fetch('/api/health', HEAD)`, `AbortController`, and online/offline/Network-Information listeners.
Call sites: `OfflineProvider.tsx:91` (mounted once at `FairwayDashboardShell.tsx:726`) and
`new-round-client.tsx:155`, inside that same subtree. Both default to 30000ms
(`use-connection-status.ts:74`). A third instance, `OfflineSyncStatus.tsx:210-213` (60000ms), is
dormant only because the sole `OfflineProvider` mount passes `showSyncStatus={false}`. The periodic
effect (`:277-306`) never checks `document.visibilityState` — unlike the repo's own
`useVisibilityAwareInterval.ts` (present, unused here) and sibling pollers
(`notification-badge-context.tsx:228-231`, `useNotifications.ts:147-161`) which do gate on visibility.
Fix: module singleton mirroring `getSyncEngine()`, or expose through `OfflineProvider`'s context;
route through `useVisibilityAwareInterval`; delete the independent call in `new-round-client.tsx`.
Owner A02 + A05. C01, C02. T05, T23.

**A11-002 (P1, SOURCE, ties G01/G02)** — two uncoordinated stale-server-action reload paths race on
overlapping error text under **different guard keys**.
`StaleDeploymentRecoveryScript` (inline `beforeInteractive`, root layout) matches
"server action" + "not found on the server"/"was not found" (`isStaleDeploymentError:30-45`) and
reloads via `reloadFresh():115-149`, guarded by `'chunk-error-reload'` (`:8-9`). Separately
`error-logging.ts`'s `isStaleServerActionError` (`:152-169`) matches an overlapping pattern and calls
`softReloadForStaleServerAction()` (`:527-566`) from `setupGlobalErrorHandlers` (`:630-679`), guarded
by `STALE_ACTION_RELOAD_KEY` (`:508`). **The comment at `error-logging.ts:499-506` names the exact
invariant this violates** ("there must be exactly one source of truth… otherwise two paths can each
first-reload") — the inline script simply isn't wired to the exported key. Neither handler calls
`stopImmediatePropagation`. Owner A02. C09, C01. T01, T02.

**A11-003 (P2, SOURCE)** — opening Calendar doubles notification-poll work.
`NotificationBadgeProvider` polls every 45s (`notification-badge-context.tsx:59`), visibility-gated
(`:228-231`), and its own comment (`:29-36`) says `NotificationBell` should read the context rather
than adding a second poll. `NotificationCenter` (`calendar/NotificationCenter.tsx:107-110`) instead
calls `useNotifications({pollInterval:30000})` against a different action (`getNotifications`),
mounted from `PremiumCalendarClient.tsx:1161/1253` — mutually exclusive by `isMobile`, still
concurrent with the badge provider. `PremiumCalendarClient.tsx:1228-1237` confirms this is a known
unresolved stopgap. Owner A07 + A02. C10. T05.

**A11-005 (P2, SOURCE/RISK)** — `PostHogProvider.tsx:20-27`'s `posthog.init` never sets
`autocapture:false` or any text mask, so every click app-wide is eligible for default autocapture of
element text and attributes. Datadog RUM (`src/lib/datadog/index.ts:46-63`) does set
`defaultPrivacyLevel:'mask-user-input'` with `sessionReplaySampleRate:20` — a real decision, but it
masks form **input** values only, not general on-screen text, so private text rendered outside an
`<input>` is protected by neither system. Whether PostHog session recording is toggled on remotely is
**BLOCKED** — dashboard-side, no credentials. Owner decision, not a unilateral change; no new SDK.

**A11-004 (P3, SOURCE)** — `FairwayTravel.tsx:296-310`'s `handleExportCSV` calls
`URL.createObjectURL` (`:304`) with no `revokeObjectURL` anywhere in the file; one blob URL leaks per
export for the tab's lifetime. The correct pattern already exists in
`PracticePrintExport.tsx:129-132` and `FairwayDocuments.tsx:676-683`.
**Owner UNASSIGNED — `FairwayTravel.tsx` is named in no Section-6 work order. A00 to route.** T23.

**A11-006 (P3, PASS record)** — `sync-engine.ts:1271-1279`'s `getSyncEngine()` is a proper module
singleton; constructor listeners (`:200-205`) and `start()`'s interval (`:214-227`, guarded) run once
regardless of call-site count. Cited as the reuse target for A11-001's fix.

**A11-007 (P3, SOURCE)** — `globals.css:732-737`'s `.card { transform: translateZ(0); }` is the named
blanket-GPU-layer anti-pattern, but its live consumers are legacy/admin (`golf/admin/crm`,
`golf/join`), **not** the canonical `src/components/ui/card.tsx` used across the in-scope mobile
dashboard. Owner A03. Scoped correctly rather than over-claimed.

**A11-008 (P2, RISK)** — `PremiumCalendarClient.tsx:~1133-1147`'s main content container carries a
**persistent** `backdropFilter:'blur(24px)'` — not a transient overlay. 32 files / ~25 call sites
repo-wide use similar 20-40px blurs. Cost concern only, routed to A03. T25.
