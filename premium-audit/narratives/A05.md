## Addendum — A00 follow-up: A05-008 blast radius (traced, not inferred)

**Nothing downstream ever flags a 0-yardage hole.** The only visible trace is an unflagged literal:

- `FairwayScorecardHeader.tsx:268` renders the raw value — a 0-yardage hole shows `0 yds` as plain
  fact, styled identically to any other hole.
- `FairwayScorecardHeader.tsx:244` — the aria-label likewise reads "…0 yards…" with no anomaly
  framing, so assistive tech gets no signal either.
- The progress math **actively conceals it**: `FairwayShotTracking.tsx:542`
  (`const totalYards = currentHole.yardage || 1;`) and `FairwayHoleHero.tsx:110`
  (`const L = currentHole.yardage || 1;`) substitute 1 for a falsy yardage to dodge divide-by-zero,
  so the hole behaves as a 1-yard hole (≈100% progress after any shot) with no indication this is a
  data fault rather than a very short hole.
- `FairwayRoundSubmitOverlay.tsx`, `FairwayRoundSummarySheet.tsx`, `FairwaySaveRoundModal.tsx`:
  zero `yardage` matches. No completion-time or summary-time signal.

This **raises** A05-008's severity rather than lowering it: the defect is not "skips one review
screen", it is "skips the review screen and nothing downstream ever surfaces the result."

### A05-015 (P1, SOURCE) — second, more permissive skip-to-tracking gate

Found while tracing the above. `new-round-client.tsx:1016-1034` (`handleQuickPickConfirm`, the
recent-courses quick-pick path) is a separate gate from the cloud-tee path in A05-008. Its check is:

    hasValidYardages = course.holeConfigs?.some(h => h.yardage > 0)

`.some`, not `.every` — so a saved course with even one nonzero-yardage hole among 18 skips straight
to `'tracking'` with the remainder left at whatever they were, potentially 0. Same downstream
invisibility applies. Numbered separately by A00 rather than folded into A05-008, because it is a
different call site with a different (and weaker) predicate, and a fix to one does not fix the other.
