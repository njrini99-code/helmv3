## Metric lineage — GIR% at career scope

| Field | Value / source |
|---|---|
| Metric key | `girPercentage` (career, scope `overall`) |
| Raw source rows | `golf_shots`/`golf_holes` joined across `golf_rounds`, read by `getDetailedStats` → `calculateStatsFromShots` |
| Calculation | `src/lib/utils/golf-stats-calculator-shots.ts:2636` — `safePercent(stats.girTotal, stats.girOpportunities)` |
| Inclusion rule | a round counts toward `roundsPlayed`/history even if scorecard-only; it contributes to `girOpportunities` only with real recorded hole data — **"rounds" and "GIR opportunities" are different populations** |
| 9/18 normalization | `holesInRound = round.roundInfo.holes_played ?? round.holes.length`; `is9Hole = holesInRound <= 9` (`:1884-1885`) gates the 9/18 buckets. GIR opportunities accumulate per real recorded hole, so a 9-hole round contributes proportionally — not dropped, not double-weighted |
| Completion status | `truncated` flag (type at `:474`) set when the read caps at the most recent 100 rounds; surfaced as an `InlineNotice` at `StatsSpineStage.tsx:594-598` |
| Denominator | `girOpportunities`, a real per-hole count — NOT `roundsPlayed`. Not exported through `LedgerInput`/`SpineLedgerRow`, so the UI cannot show it (A06-007) |
| Unknown values | `safePercent` returns `null` when `attempts === 0`; `fmtPct` (`buildStatsViewModel.ts:70-72`) renders an honest em-dash — never a fabricated 0% |
| Cache layer | **none found** — no `unstable_cache`/tag cache wraps `getDetailedStats`/`getTrendAnalysis`/`getPlayerStandingRows`/`getPlayerLeakMaps`. Each read hits the DB fresh per server action (`stats-dashboard.ts:64-119`, `Promise.all` of 8 `settleWithin`-bounded reads). Client-side it lives only in `StatsSpineStage` React state (`:129`) |
| Display formatter | `fmtPct` — `Math.round(n)` + `%`, whole-percent, no decimals |
| Label | "Greens" (`buildStatsViewModel.ts:158`) — abbreviated, no "in regulation", no denominator or sample annotation |
| Comparison baseline | team-avg/PGA-Tour lives on a separate `PlayerStandingRow`, and only for `sg_*` metrics in this surface. GIR has no team/Tour comparison in the Spine |
| Timestamp / validity | **none** — no `computed_at` or freshness field anywhere in the bundle envelope or on `GolfStats` |
| Scope comparability | career figure is fully replaced by `RoundStatReport` at round scope, never shown side-by-side under one label; `StatsSpineStage.tsx:453-457` tells the user which figures are cross-round-only. **Correct — no forced equality, no silent mislabeling** |

C07 fields absent from display for this metric: a sample/denominator distinct from "Rounds" (A06-007),
a timestamp/validity state (A06-008), and a calculation/model revision id — no version tag exists on
`GolfStats` or the bundle envelope for **any** metric.

## Scope/retry contract, as observed

- The round-scope picker (`StatsSpineStage.tsx:310-340`) is intended to stay mounted in every state.
  Correctly wired into `loading` (`:345`), `scopedRound` (`:406`), and success (`:577`);
  **incorrectly omitted** from `loadError` (`:354-370`) and `isColdStart` (`:462-478`) — A06-005.
- Exactly ONE `loading` boolean governs the entire page skeleton. No per-region loading state exists,
  despite `leakError` already proving the codebase will track a scoped error flag. Retry granularity is
  binary: any retry re-runs the full 8-read `loadAll` and re-triggers the full skeleton — A06-004.
- Round-scope switching deliberately does NOT re-scope cross-round data (standing / 30-day trend /
  patterns); only `detailedStats` and `sprayData` narrow. Documented at `stats-dashboard.ts:55-63` and
  surfaced at `StatsSpineStage.tsx:453-457`. **This part is correct and intentional** — the defect is
  only that scope switching still triggers the full-page loading state.
- No request-generation guard anywhere in the scope-switch path (`loadAll`, `:122-182`) even though the
  sibling round-options effect (`:186-207`) already implements the correct `cancelled`-closure idiom.
  A06-003's fix should reuse that exact idiom, not invent one.
- Net: the code has all the pieces (per-region error flags, a working cancellation idiom, honest
  partial-fetch handling) but does not compose them. Both fixes are additive, not a rewrite.

## Contracts requested

**C02 (scoped read)** — formalize the request-generation/cancellation idiom so `loadAll` (A06-003)
adopts it rather than inventing a second mechanism: a generation-ref (increment on fetch start,
capture at call time, apply setState only if still current), functionally identical to the
`cancelled`-closure flag already used correctly at `StatsSpineStage.tsx:186-207`. A02 to bless this
(or an AbortSignal equivalent) as canonical so every A04–A09 adapter uses one mechanism.

**C07 (metric provenance)** — two fields that exist in no type read this pass: (a) a per-metric
sample/denominator distinct from a headline rounds count, e.g. an optional `sampleCaption`/
`denominator` on `SpineLedgerRow` so "Fairways: 61%" can carry "(142 attempts)" separately from
"Rounds: 18" (A06-007); (b) a validity-state/timestamp (`computedAt`/`staleAfter`) usable by any
metric-bearing type, not just the team board's bespoke `teamStatsFreshness` (A06-008). Also: C07
should define what a displayed confidence percent may claim — interval-hit-rate vs. point-probability
— since the engine computes and validates the former but the UI sentence (A06-006) doesn't say so.

**C08 (material/control)** — A03 to make the single-padding-owner decision for `CoachHelmShell`
explicit, since it is mounted unconditionally by ~15 coach and player surfaces. A fix scoped only to
the Stats route would leave the same double-gutter class of bug on every other mount.
