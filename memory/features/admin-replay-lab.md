## Current State

A fixture-and-manifest format for proving a historical incident's repair
commit actually fixes what it claims to: check out the commit before the
fix in an isolated, disposable worktree, overlay the repair's own
regression test, run it and expect it to fail; check out the fix commit in
the same worktree, re-apply the fixture, run it again and expect it to
pass. Never touches production — no Supabase client, no Vercel API, no
external side effect anywhere in the loop.

Ships with 3 backfilled replays (`replay/manifests/*.yml`) covering
`shot_tracking` (2) and `qualifiers` (1) incidents from `memory/incidents/`.
Shadow execution (running the analysis path against recorded inputs to
observe a behavioral diff, not just pass/fail) is explicitly deferred —
it needs side-effect sinks for every external integration this codebase
has, none of which exist yet.

## Primary Entry Points

### Tooling (not a route — `replay/` is a top-level, non-`src/` directory)

- `replay/README.md` — the lab's own docs, read this first
- `replay/schema/manifest.schema.json` — the manifest contract
- `replay/manifests/*.yml` — one per replay
- `replay/fixtures/<feature_id>/<replay_id>/**` — files a manifest overlays
- `replay/runners/run.mjs` — the CLI runner (worktree, fixture, test, proof)
- `replay/runners/manifest.mjs` — pure manifest load/validate, shared by
  `run.mjs` and the vitest meta-test
- `replay/runners/gen-coverage-index.mjs` — regenerates the Bridge panel's
  bundled data index; **no CI drift check wired for this yet** — re-run by
  hand after editing a manifest or a proof
- `replay/proofs/*.json` — written only by a real `run.mjs` execution;
  absence means "not yet run", never "passed"

### Bridge surface

- `src/lib/admin/replay/coverage.ts` — read model over the generated index
- `src/lib/admin/replay/coverage-index.generated.ts` — **DO NOT EDIT**,
  regenerated by `gen-coverage-index.mjs`
- `src/components/admin/replay/ReplayCoveragePanel.tsx` — the per-replay
  row list (StatusPill tones: `reproduced` success, `inconclusive` warning,
  `not-yet-run` neutral — never green by default)
- `src/app/admin/self-heal/page.tsx` — gained a "Replay coverage" `Surface`
  section (additive; the file remains owned by `admin_selfheal`)

## Known limitations

- No live replay run has been executed as of this feature's introduction —
  `~/worktrees/helmv3` had 13 GiB free against the 17 GiB
  `scripts/ensure-worktree-deps.mjs` requires for a real `npm ci`. All 3
  manifests render `not-yet-run` on the Bridge panel, honestly.
- `coverage-index.generated.ts` has no automated drift check (unlike the
  `docs:check` AUTOGEN family) — a manifest or proof change that isn't
  followed by `node replay/runners/gen-coverage-index.mjs` will silently
  desync the Bridge panel from the actual corpus.
- `run.mjs`'s failure-mode classification (`classifyFailure` in
  `manifest.mjs`/`run.mjs`) is a string-matching heuristic over test
  output, not a structured parse — good enough to distinguish
  "missing-export" from "assertion" for this corpus, not guaranteed for an
  arbitrary future test framework's output shape.
