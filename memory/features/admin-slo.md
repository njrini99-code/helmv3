# Feature: Admin SLO Center

> Added 2026-09-03, Bridge Control Plane Phase D
> (`docs/ai-system/CONTROL_PLANE_IMPLEMENTATION_PLAN_2026-09-03.md` §2). A new
> sub-capability alongside `admin_reliability_collector`,
> `admin_incidents`, `admin_selfheal` under the `admin_platform` registry
> split (ADR-2026-09-03-control-plane-owner-decisions,
> `ADMIN_PLATFORM_REGISTRY_GRANULARITY`). Reads the reliability collector's
> own record, `get_feature_health()`, and the golf-round flight recorder —
> it introduces no new writer and no new table.

## Status

- active

## Current State

Four independent read models rendered on one page, `/admin/slo`:

- **Error budget** (`src/lib/reliability/error-budget.ts`) — a rolling-window
  burn rate per `FeatureKey`, computed from the last N
  `background_job_logs` `reliability-snapshot` rows against
  `TIER_THRESHOLDS.redFp` (`feature-registry.ts`). Not an errors-over-requests
  SLO — the collector carries no traffic denominator, only grouped
  fingerprint counts.
- **Golden-path health** (`src/lib/admin/slo/golden-path-health.ts`) — rolls
  the 8 journeys in `memory/journeys/golden-paths.yml` (via the generated
  `golden-paths.generated.ts`) up against the SAME error-budget report. A
  stage whose `feature_id` does not resolve to a real `FeatureKey` (see the
  module's own doc on the registry.yml/`FeatureKey` namespace gap) reads
  `'unknown'`, never a fabricated pass.
- **Silence detection** (`src/lib/admin/slo/silence-detection.ts`) —
  classifies each feature's `get_feature_health()`-computed
  `heartbeatAgeHours` against its own tier default or
  `heartbeatStaleHoursOverride`. Reuses that RPC's existing computation; does
  not re-derive heartbeat staleness independently.
- **Trace funnels** (`src/lib/admin/slo/trace-funnels.ts`) — one
  `helm_debug_list_traces` RPC call per golf-round workflow (bounded, 100
  runs), tallying status counts, `missing_required_step_count > 0` runs, and
  ranked `failure_step` drop-offs. A DIFFERENT read of the RPC `/admin/traces`
  already uses to open one trace at a time.

Executable invariants (Phase D.4.3) render on `/admin/health`'s Invariant
Lattice instead of being duplicated on this page — see
`admin_reliability_collector`'s `src/lib/reliability/invariants/**` for the
round-graph checks and `memory/invariants/registry.yml` for the declarative
index.

## Core Data

- `background_job_logs` (`reliability-snapshot` rows) — error budget's only
  input, via `fetchReliabilitySnapshot()` (already owned by
  `admin_reliability_collector`).
- `get_feature_health()` RPC — silence detection's only input, via
  `fetchFeatureHealth()` (already owned by `admin_platform`).
- `helm_debug_list_traces` RPC — trace funnels' only input.

No new table, no new column, no new RPC. This feature is a synthesis layer.

## Business Rules

- **An error budget with zero readable collector windows is `'unknown'`,
  never `'ok'`.** A feature with genuinely zero observed errors across N
  *readable* windows is a real, bounded `'ok'` claim about error volume — but
  `windowsReadable === 0` (every considered window blind or unparseable)
  must never collapse to the same state. See `error-budget.ts`'s own header
  for the full honesty contract (floor accounting via `countIsFloor`,
  degraded/partial windows still count but mark their features as floors).
- **`ReliabilityRun.invariants`/`countIsFloor` are additive fields that do
  NOT bump `ReliabilityRun.version`.** A row written before Phase D.4.3
  shipped has neither key; `parseRun` (`src/lib/admin/data/reliability.ts`)
  only checks `version === 1`, so both fields must stay optional forever, or
  every historical row becomes unreadable.
- **The invariant runner is a fourth `Promise.allSettled` arm, run alongside
  — not inside — the existing 3-source array in `collect.ts`.**
  `ReliabilitySource`/`sourceNames` is a closed 3-element union indexed
  positionally; widening it would ripple into `summarizeSources`,
  `worstStatus`, and the Reliability tab's coverage matrix. See `collect.ts`'s
  own comment at the `Promise.all([...])` call site.
- **Golden-path health does not invent feature-alias mappings.**
  `memory/registry.yml`'s `features:` namespace (what `golden-paths.yml`'s
  `feature_id` is validated against) and `feature-registry.ts`'s `FeatureKey`
  union are different taxonomies that only partially overlap. A stage whose
  `feature_id` has no entry in `FEATURE_AREA_ALIASES` and is not itself a
  `FeatureKey` reads `'unknown'` with a stated reason — closing that gap
  belongs to whoever owns `FEATURE_AREA_ALIASES`, not this module, and a
  silent guess would risk misattributing one feature's error volume to
  another's stage.
- **Silence detection never re-derives heartbeat staleness independently of
  `get_feature_health()`.** `FeatureHealth.drillIn.heartbeatAgeHours` is the
  single source of truth for "how long since this feature's heartbeat table
  moved"; this module only classifies that number against
  `TIER_THRESHOLDS`/`heartbeatStaleHoursOverride`, exactly the same
  tier/override input the RPC itself already used to compute the age's
  significance.
- **A `seasonalEmpty` feature past its threshold reads `'healthy_quiet'`,
  never `'stale'`**, regardless of age — an expected off-season silence must
  never surface as a possibly-dead emitter.
- **`golden-paths.generated.ts` is never hand-edited.** It is generated from
  `memory/journeys/golden-paths.yml` because `memory/**` is not part of the
  Vercel function bundle — a server component reading the YAML directly would
  work locally and fail in production. `npm run knowledge:golden-paths-generate:check`
  is the drift gate.
- **Trace funnels is a fleet read, not a duplicate Flight Recorder.**
  `/admin/traces` opens one trace's containment tree; this page asks where
  attrition concentrates across the last 100 runs per workflow. Both read the
  same `helm_debug_list_traces` RPC independently — this module does not
  import from `src/app/admin/actions/golf-tracer.ts` except its `FlightTraceRun`
  type, to avoid coupling to a page it does not own.

## UI Contract

- Four sections, one `PanelBoundary` each, so one source failing (a blind
  reliability collector, an unreachable `get_feature_health()`, a rejected
  trace-funnel fetch) degrades only its own section.
- Error budget and silence detection both show the worst rows first and
  collapse the rest behind a `<details>` disclosure — a page whose default
  view is 86 rows of mostly-green noise buries the ones an operator needs.
- Golden-path health always renders exactly the 8 seeded journeys (`active`
  or `collecting` — the registry's own status, never blended into the
  computed health state as if it were a live reading).
