# `memory/` — what's in here and how much to trust it

The knowledge base `CLAUDE.md` and `AGENTS.md` route sessions into. **Read this
before trusting anything below it.**

---

## The one rule

> **The code is the source of truth. The `AUTOGEN` blocks track it
> automatically. Everything else is someone's memory of it.**

Three tiers, and the difference is not cosmetic:

| Tier | Files | Trust |
|---|---|---|
| 🟢 **Generated** | the `AUTOGEN:*` blocks inside `glossary.md`, `projects/golfhelm.md`, `context/golfhelm-database.md` | **Authoritative.** Regenerated by `scripts/regen-docs.mjs` from `src/lib/types/database.ts`, which `npm run db:types` pulls from the live database. Use for any name, column, route, or count. |
| 🟡 **Machine-checked prose** | everything else in `memory/**` | Hand-written, but two CI gates verify its *claims*. Bad names and dead paths are counted, baselined, and blocked from growing. |
| 🔴 **Unverified** | `context/*` narrative sections outside AUTOGEN blocks | Explicitly self-limiting — several carry their own "do not trust this for names" headers. Read for *intent*, never for identifiers. |

## What the gates found

Two things are measured, not assumed. Both run on every PR:

| Gate | Command | Finding | Baseline |
|---|---|---|---|
| Schema drift | `npm run docs:schema-drift` | **59 database identifiers** named here don't exist in production — confirmed absent from `pg_class`, `pg_proc`, `pg_type` | `.doc-schema-baseline.json` |
| Path drift | `npm run docs:path-drift` | file paths named here don't resolve (count: see baseline) | `.doc-path-baseline.json` |

Both counts **may only go DOWN**. Anything new fails CI.

**These are not typos.** Phantom tables are rendered with full columns, FK
targets and RLS policy names, formatted identically to real ones. A session
reading them writes confident, detailed, broken code. That is the failure these
gates exist to bound.

⚠️ **A missing table does not reliably mean a missing feature.** Recurring events
are fully implemented — on `golf_events.recurring` / `recurrence_rule` /
`parent_event_id` — while `golf_recurring_events`, the table the docs named,
never existed. Check the code before concluding anything is absent.

⚠️ **Do not bulk-repoint dead paths by basename search.** It was tried; the
nearest-name matches were build artifacts under `src/.helmdev/`. That trades a
visibly broken path for a confidently wrong one. Fix by hand.

## Layout

```
memory/
├── README.md          ← you are here
├── registry.yml       Feature routing table. AGENTS.md's entry point.
│                      Maps code paths → feature docs. 25 features.
├── glossary.md        Table/enum/type lookup. AUTOGEN blocks authoritative;
│                      the by-feature index above them is NOT (see its header).
├── context/           Gen-1 knowledge. Large, per-product.
├── features/          Gen-2 knowledge. Per-feature. PREFERRED — see below.
├── projects/          Route/action/hook inventory (AUTOGEN).
├── templates/         Blank forms for new feature/flow/rule/contract docs.
├── prompts/           Reusable prompts (docs-update, pr-review, feature-audit).
└── brand/             Logo and brand asset notes.
```

## ⚠️ Two generations exist. `features/` wins.

`context/golfhelm-features.md` (~58k chars) and `features/*.md` (16 files, ~66k)
describe **the same features**. `CLAUDE.md` routes to the first, `AGENTS.md` →
`registry.yml` routes to the second.

**`AGENTS.md` is the repo constitution and outranks `CLAUDE.md`, so
`features/` wins on disagreement.** Use `context/golfhelm-features.md` only for
features the registry doesn't map.

Neither is authoritative for names. The split did not create a check — it
doubled the surface: `features/calendar-events.md` reproduced all 10 of the
older doc's non-existent tables rather than re-verifying them. **Collapsing
these to one generation is real work still owed.**

## Where to go

| You need… | Read |
|---|---|
| A table, column, enum, or type name | `glossary.md` **AUTOGEN blocks** → or `src/lib/types/database.ts` directly |
| Every column of every table | `context/golfhelm-database.md` **`AUTOGEN:columns`** |
| How a golf feature behaves | `registry.yml` → the mapped `features/*.md` |
| Baseball behaviour | `context/baseballhelm-features.md` + `docs/audits/BASEBALLHELM_CANONICAL_SPEC.md` |
| CoachHelm AI internals | `context/coachhelm-ai.md` |
| Where code lives | `projects/golfhelm.md` (AUTOGEN) or `docs/REPO_MAP.md` (⚠️ 192 commits stale) |
| To add a feature doc | copy from `templates/` and register it in `registry.yml` |

## Retired / corrected

- **`context/baseballhelm-database.md` §2d is RETIRED schema.** All 35
  `baseball_lift_*` / `baseball_strength_*` tables are gone from production —
  exactly one survivor, `baseball_exercises`. The live system is
  `helm_lifting_*` (33 tables). The section is kept for design intent only; the
  source code carried the correct story in comments the whole time.
- **`glossary.md`'s by-feature index** was last hand-verified **2026-02-13** and
  names 20 tables that do not exist. Its AUTOGEN blocks are fine.
- **`context/golfhelm-database.md`'s header** used to state a table count that
  contradicted its own AUTOGEN block 15 lines below. Counts now live in the
  block only.
- The enum block reported **6 enums when the schema had 18** for roughly six
  months, under a `DO NOT EDIT — regenerated` stamp. Fixed 2026-08-19;
  `extractEnums()` now throws rather than under-report, and
  `scripts/__tests__/regen-docs-enums.test.mjs` locks the input shapes.
