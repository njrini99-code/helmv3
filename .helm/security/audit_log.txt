## 2. Key Technical Concepts

- **Row Level Security (RLS)**: PostgreSQL security feature that restricts which rows users can access
- **Supabase**: PostgreSQL-based backend-as-a-service with built-in RLS support
- **RLS Policies**: SQL statements defining access rules (USING clause for SELECT/UPDATE/DELETE, WITH CHECK for INSERT/UPDATE)
- **SECURITY DEFINER Functions**: PostgreSQL functions that run with elevated privileges, bypassing RLS
- **auth.uid()**: Supabase function returning the authenticated user's ID
- **Horizontal Access Control**: Preventing User A from accessing User B's data
- **Vertical Privilege Escalation**: Preventing users from gaining admin privileges
- **Team-scoped Access**: Data access restricted by team_id membership
- **Policy Coverage**: Ensuring all operations (SELECT/INSERT/UPDATE/DELETE) have policies
- **Permissive Policies**: Policies using USING (true) that don't restrict access
- **Next.js 16**: Application framework (App Router with Server Actions)
- **TypeScript 5.9.3**: Strict type checking enabled
- **Migration History**: 91 migrations showing RLS was intentionally disabled in migrations 061, 062, and 078
